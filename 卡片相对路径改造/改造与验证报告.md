# 卡片相对路径改造与验证报告

日期：2026-07-27

## 最终需求

- 应用只使用一个 `app-data.json`。
- 卡片不区分本机或共享类型。
- 文件引用只保存相对于 `app-data.json` 所在工具目录的路径。
- 同盘文件允许使用 `../` 指向工具目录外。
- Windows 跨盘符不存在相对路径，因此不允许创建跨盘卡片，并显示明确错误。
- 文件移动后无法打开时，继续使用现有失败和重新关联流程。

## 实现结果

1. `AppData.version` 从 1 升级到 2。
2. `FileReference.absolutePath` 改为 `FileReference.relativePath`。
3. Main 进程在选择文件时把绝对路径转换为相对路径。
4. 打开、文件管理器定位和 HTML 标题读取前，以工具目录为基准解析真实路径。
5. 新建、去重和重新关联统一使用规范化相对路径。
6. Windows 跨盘选择返回“所选文件与工具不在同一磁盘，无法创建相对路径”，不写入卡片。
7. 保留 V1 数据读取兼容：同盘绝对路径在加载时转换成 V2 相对路径。
8. 正式数据模型、系统桥接契约和产品术语已同步更新。

## 已确认边界

- 相对路径以 `app-data.json` 所在目录为唯一基准。
- 工具目录整体移动或 Git 仓库克隆到新位置时，只要工具和教程的相对目录结构保持不变，卡片仍可打开。
- 同盘目录外文件可以创建卡片，但工具目录或目标文件移动后，相对关系可能失效。
- Windows 跨盘文件无法表达为真正的相对路径，因此创建和重新关联时会被拒绝。
