# Matt Pocock Skills 实战教程设计说明

## 目标

制作一份中文、单文件、可离线打开的 HTML 实战手册，帮助怡哥在不安装 `mattpocock/skills` 的前提下：

1. 理解技能本体安装与项目级配置的区别。
2. 看清 Matt Pocock Skills、gstack、Superpowers 三套体系的定位与冲突。
3. 根据任务阶段选择唯一主流程，避免嵌套编排。
4. 快速检索官方公开的全部 22 个 Matt Pocock Skills。
5. 通过一个端到端案例掌握选择、调用和收尾方法。

## 成功标准

- 覆盖 22 个公开技能，无遗漏、无虚构。
- 每项包含：类别、调用主体、作用、适用时机、输入、输出、示例调用、重叠对象、建议策略。
- 明确区分用户主动调用与模型自动调用。
- 提供三体系冲突矩阵和阶段路由建议。
- 提供“建议试用 / 按需启用 / 暂缓启用”分级，不把主观建议冒充官方结论。
- 页面支持关键词搜索、类别筛选、调用类型筛选、冲突等级筛选和卡片展开。
- 375px、768px、1440px 视口下无横向溢出或关键信息缺失。
- 所有事实性内容可追溯到官方仓库；对 gstack、Superpowers 的比较以本机已安装版本为准并标注日期。

## 范围

### 包含

- 安装范围与配置生命周期。
- 三体系定位图。
- 重叠与风险矩阵。
- 分阶段唯一主流程建议。
- 一个“三体系对照案例”：从模糊需求到规格、实现、测试、审查、交付。
- 22 技能速查库。
- 安装前检查清单和建议的最小试用组合。

### 不包含

- 实际安装、运行或修改 Matt Pocock Skills。
- 对 GitHub、Linear 等外部系统的真实写入。
- 对仓库未公开能力的猜测。
- gstack、Superpowers 全量技能百科；仅呈现与 Matt 技能有关的映射。

## 信息架构

1. **首屏结论**：是否每项目安装、推荐采用策略、22 技能总览数字。
2. **安装模型**：项目级复制、用户级复用、每仓库 setup 三层说明。
3. **体系定位**：Matt 侧重可组合工程纪律；gstack 侧重端到端工程与交付；Superpowers 侧重强制流程门禁。
4. **冲突地图**：按自动触发、硬门禁、产物、Git、审查、上下文六类呈现。
5. **采用建议**：试用、按需、暂缓三组，并解释判断依据。
6. **对照实战**：同一功能需求在三套体系中的路径，以及推荐的混合但不嵌套方案。
7. **技能速查**：22 张可筛选卡片，支持展开查看输入、输出、提示词和冲突建议。
8. **落地规则**：每阶段唯一主技能、单一事实源、显式调用优先、收尾工具唯一。
9. **来源与版本**：官方仓库链接、核验日期、版本信息和免责声明。

## 交互设计

- 顶部粘性目录，移动端折叠。
- 速查区提供即时搜索和组合筛选；结果数量实时更新。
- 技能卡默认展示决策所需摘要，展开后显示完整实操信息。
- 冲突矩阵在窄屏转换为分组卡片，避免不可读的宽表格。
- 提供“复制提示词”按钮；复制成功采用非阻塞状态提示。
- 不依赖框架或远程 JavaScript；禁用脚本时核心内容仍可阅读。

## 视觉方向

- 定位为“工程作战手册”，不是营销落地页。
- 浅色纸张基底，深墨色正文，蓝色用于操作和导航，橙红色仅用于冲突警示。
- 强调信息层级、表格可读性和长文阅读舒适度；不使用渐变、装饰性图形或卡片阴影堆叠。
- 中文正文优先使用系统字体栈，等宽内容使用本地 monospace，保证离线可用。

## 数据结构

技能速查数据以内嵌 JavaScript 对象维护，每项字段为：

```text
id, name, category, invocation, purpose, whenToUse,
inputs, outputs, example, overlaps, conflictLevel, recommendation, source
```

页面渲染、筛选和搜索均基于这一份数据，避免卡片内容与统计数字形成双重事实源。

## 验证

- 内容检查：技能数量为 22；用户调用和模型调用分类合计一致。
- 来源检查：每个技能链接指向对应官方 `SKILL.md`。
- 交互检查：搜索、四类筛选、展开、复制、目录跳转。
- 响应式检查：375、768、1440 三个宽度。
- 可访问性检查：标题层级、键盘焦点、按钮标签、对比度、减少动态效果。
- 文件检查：HTML 为单文件，除外部参考链接外无运行时网络依赖。
