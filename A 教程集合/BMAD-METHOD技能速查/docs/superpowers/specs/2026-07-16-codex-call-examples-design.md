# BMAD 技能速查：Codex 调用示例与阶段筛选设计

## 目标

把每张技能卡片原有的【如何使用】替换为一条可直接复制到 Codex 的 `$技能名` 调用示例，并将阶段筛选固定为符合 BMAD 工作顺序的中文顺序。

## 成功标准

- 52 个技能都提供独立、具体、可直接粘贴到 Codex 的调用示例。
- 调用示例均以 `$技能名` 开头；不保留原【如何使用】文案。
- 每张卡片的调用示例旁均有复制按钮。
- 复制成功后按钮短暂显示“已复制”；失败时提示用户手动复制。
- 表格视图的【调用】列改名为【调用示例】，内容与卡片一致。
- 阶段筛选从上到下固定为：分析、规划、方案、实施、任意阶段。
- 原数据中的“方案设计”统一改为“方案”。

## 数据设计

每个技能对象将原 `usage` 字段替换为 `example` 字段。

示例：

```text
$bmad-help 分析当前 BMAD 项目状态，告诉我下一步应该运行哪个技能。
```

要求：

- 示例必须以当前对象的 `$name` 开头。
- 示例描述一个具体任务，不使用“按技能提示执行”之类的空泛表述。
- 已废弃技能仍给出兼容调用示例，并在正文中明确推荐的新技能。
- Web Bundle 技能沿用其目录名作为 `$技能名`，同时保留“Web Bundle 单独分发”标签。

## 卡片交互

- 字段标题由【如何使用】改成【调用示例】。
- 示例放在独立代码样式容器中，保持等宽字体并允许自动换行。
- 容器右上角放置“复制”按钮。
- 按钮通过唯一的 `data-copy-name` 找到对应技能，复制内存数据中的完整 `example`，不依赖筛选后的数组序号，也不从渲染后的 DOM 反解析文本。
- 优先使用 `navigator.clipboard.writeText`；不可用或失败时回退到隐藏 `textarea` + `document.execCommand('copy')`。
- 成功状态显示“已复制”，约 1.5 秒后恢复“复制”；失败状态显示“复制失败”，并保留页面文本供手动选择。

## 阶段筛选

- 不再对阶段值调用通用字母排序。
- 使用固定数组：`['分析', '规划', '方案', '实施', '任意阶段']`。
- 生成筛选项时只加入数据中实际存在的值，但必须保持固定数组顺序。
- 所有原“方案设计”数据改为“方案”，筛选和卡片标签使用同一字段，避免显示与过滤不一致。

## 测试设计

先让以下校验在旧实现上失败，再实施：

1. 52 个技能都存在非空 `example`，且以“`$` + 当前技能 `name`”开头。
2. 数据对象不再依赖 `usage` 作为展示字段。
3. 页面包含复制按钮与复制状态处理函数。
4. 卡片渲染每个技能时生成一个复制按钮。
5. 表格列标题为【调用示例】。
6. 阶段固定顺序为：分析、规划、方案、实施、任意阶段。
7. 数据中不存在“方案设计”。
8. 原有 52 个技能覆盖、来源路径、唯一性和前端脚本语法校验继续通过。

## 范围外

- 不改变技能数量、分类、用途、输入、输出、角色和来源。
- 不增加多示例切换、收藏、导出或批量复制。
- 不修改 BMAD-METHOD 源码快照。
