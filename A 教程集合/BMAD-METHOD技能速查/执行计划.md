# BMAD-METHOD 技能速查 HTML：执行计划

## 问题是什么

从 `bmad-code-org/BMAD-METHOD` 当前仓库中识别全部 BMAD 技能，并整理为一份中文、可离线打开的 HTML 速查文件。每项至少包含：技能名称、技能用途、输入、输出、使用场景、使用角色，并保留来源定位，避免把“技能、工作流、智能体、命令”混为一谈。

## 成功标准

- 技能清单可追溯到仓库中的技能定义或官方文档，没有凭印象补全。
- 每项均包含：名称、所属模块、用途、输入、输出、典型场景、适用/执行角色、Codex 调用示例、来源链接。
- HTML 为单文件，中文展示，可离线打开，并支持关键词搜索及按模块、角色、场景筛选。
- 明确标注整理时所依据的 BMAD 版本、分支或提交时间，方便日后判断是否过期。
- 完成去重和覆盖检查；不确定信息明确标注，不作推测。

## 范围

### 默认纳入

- 仓库当前正式版本中，所有官方模块内可被用户或智能体调用的 `skill` 定义。
- 核心 BMad Method，以及仓库内随正式安装分发的官方模块。
- 与技能直接关联的入口、角色、输入产物和输出产物。

### 默认不纳入

- 单纯的内部脚本、测试夹具、开发工具和已废弃内容。
- 仅作为智能体人格定义、但本身不可作为技能调用的文件。
- 第三方扩展模块，除非它们已经作为该仓库正式发行内容登记。

## 约束条件

- BMAD V6 正在快速演进；必须固定版本口径，不能笼统声称“永久全部”。
- 仓库同时存在 skills、workflows、agents、modules 等概念，需先建立分类规则。
- 交付物仅写入本对话任务文件夹：`BMAD-METHOD技能速查/`。
- 本次只创建本地 HTML 文件，不修改 BMAD 原仓库，不提交、不推送。

## 初步方案

1. 固定仓库基线：优先采用最新稳定 Release；同时记录 tag、发布日期和提交号。
2. 获取仓库完整目录，读取技能清单、各技能定义、模块清单及相关官方文档。
3. 建立技能主表，并用“文件定义 → 模块注册 → 文档说明”三层证据交叉核验。
4. 对每个技能提取或归纳：调用名、用途、必需/可选输入、产出、前置条件、典型场景、执行角色、协作角色。
5. 生成单文件 HTML：顶部统计、搜索框、筛选器、技能卡片/表格、来源链接、版本说明。
6. 执行完整性校验：数量对账、重复调用名、孤立定义、缺字段、失效链接、HTML 基础语法与脚本检查。

## 待解决的问题

1. “所有技能”的口径：仅统计 V6 `SKILL.md` / skill 定义，还是将传统 workflows 与 agents 也作为可执行能力一并列入？
2. 版本口径：采用最新稳定 Release，还是直接采用 `main` 分支最新状态？
3. 展示形态：建议以可搜索卡片为主，并提供紧凑表格视图；是否需要打印样式？

## 推荐决策

- 版本采用“最新稳定 Release”，因为速查表需要可复现，`main` 可能随时变化。
- 主表严格统计正式 skill 定义；另设“关联工作流/智能体”字段，而不是把三类对象混成一张技能表。
- HTML 同时提供卡片与紧凑表格视图，并支持打印。
