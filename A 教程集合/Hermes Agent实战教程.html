把 Hermes 变成你的
可复用执行系统

Hermes Agent 不是只回答问题的聊天框。它能在终端、桌面端和消息平台上运行，调用文件、浏览器、终端与搜索工具，把反复执行的方法沉淀成技能，并跨会话保留关键事实。

从 10 分钟上手开始直接看技能实战
1 条主线安装 → 配置 → 执行 → 复用
6 个练习从研究到自动简报
0 外部依赖页面可直接离线打开
02 · FIT CHECK

什么时候值得用？

判断标准不是“能不能聊”，而是任务是否需要多步执行、工具调用、持续记忆或重复复用。

RESEARCH

资料研究与报告

让它搜索、提取、交叉核对，再输出带来源的结构化结论。

OPERATIONS

文件与终端操作

检查项目、整理文件、执行脚本、分析日志，并在修改前先给影响范围。

REPEATABLE

重复工作技能化

把 5 步以上、以后还会再做的流程保存成 Skill，下次一句命令复用。

AUTOMATION

定时监控与简报

按自然语言或 cron 表达式定时执行，并把结果发回文件或消息平台。

REMOTE

远程个人助理

部署在常开电脑或服务器，从 Telegram、Discord、Slack 等渠道下任务。

CONTEXT

长期项目协作

结合 AGENTS.md、记忆和会话历史，持续遵守同一套项目规则。

NOT IDEAL

不必用 Hermes 的情况

  • 只问一个无需工具的简单事实。
  • 任务一步就能完成，且不会重复。
  • 不能接受任何模型调用成本或联网需求。
  • 要让智能体无审批地管理高风险生产系统。
DECISION

30 秒选择法

满足下面任意两项，就值得尝试：

  • 需要 3 步以上
  • 需要读写文件或运行命令
  • 以后会重复
  • 希望跨会话记住规则
  • 需要定时或远程触发
离线边界：本教程页面本身不加载任何网络资源；但安装 Hermes、调用云端模型、联网搜索和消息平台仍需要网络与相应账号。
03 · QUICK START

10 分钟上手

Windows 推荐桌面安装器；如果更偏爱终端，再选官方 PowerShell 安装脚本。

图形化安装：最省心

打开官方安装说明，从 Hermes 官方网站下载安装器。安装器同时提供桌面应用和命令行入口。

查看官方安装说明 ↗

原生 PowerShell：命令行安装

PowerShell
iex (irm https://hermes-agent.nousresearch.com/install.ps1)
远程脚本提醒：该命令会下载并执行官方域名上的脚本。执行前确认域名完全一致；公司设备还应遵守组织的软件安装政策。

Linux / macOS / WSL2 / Termux

Shell
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash

完成后按安装器提示重新加载 shell；如命令仍找不到，关闭并重新打开终端。

配置模型与工具

最快路径是 Nous Portal；它通过一次 OAuth 配置模型，并启用搜索、图像、TTS 和浏览器工具网关。

终端
hermes setup --portal

已有其他模型供应商？在 Hermes 会话外运行 hermes model，按向导添加 API Key、OAuth 或自定义端点。

检查安装健康度

终端
hermes --version
hermes doctor
hermes status --deep

开始第一次对话

终端
hermes

首次任务建议从“只读、目标明确、结果容易核对”的任务开始。

复制第一条实战提示词

Hermes 会话
先不要修改任何文件。请检查当前目录的结构，说明：
1. 这是什么项目；2. 如何启动；3. 主要风险；4. 下一步建议。
结论必须引用实际文件路径；不确定的内容明确标注。
命令位置要分清：hermes model 在系统终端中添加供应商和凭据；/model 在聊天中切换已经配置好的模型。
04 · EXECUTION LOOP

一条可控的工作流

Hermes 的价值来自“对话 + 工具 + 复用”。你的责任是给清边界，并在关键写入点把关。

01 · BRIEF

定义任务

目标、成功标准、范围、禁止事项
02 · CONTEXT

加载上下文

项目文件、AGENTS.md、记忆、技能
03 · ACT

调用工具

搜索、文件、终端、浏览器、委派
04 · VERIFY

验证结果

测试、来源、日志、差异与风险
05 · REUSE

沉淀复用

事实进记忆，步骤进技能，项目规则进上下文文件
GOOD BRIEF

推荐任务模板

提示词模板
目标：我要得到什么。
成功标准：怎样才算完成。
范围：允许查看或修改哪些位置。
约束：不能做什么；何时必须确认。
输出：用什么格式汇报，并给证据。
CONTROL GATES

三个必须停下来的点

  • 删除、覆盖、批量移动等不可逆操作。
  • 发送消息、发布、部署、付款等外部影响。
  • 目标与现有项目规则或用户决策冲突。

出现这些情况时，先让 Hermes 给出准确目标、影响和回滚方案，再批准。

06 · SKILL LAB

技能：把“会做”变成“下次直接做”

Skill 是按需加载的操作说明。适合稳定、可重复、有明确步骤的流程，而不是保存零散事实。

FAST PATH

查找 → 检查 → 安装 → 使用

系统终端
hermes skills browse
hermes skills search arxiv
hermes skills inspect official/research/arxiv
hermes skills install official/research/arxiv
hermes skills list

安装后通常在新会话生效；需要当前会话马上刷新，可使用安装命令支持的 --now，或执行 /reset。

IN CHAT

聊天内完成同样操作

Hermes 会话
/skills
/skills install official/research/arxiv
/arxiv 搜索最近一年关于 AI Agent 长期记忆的论文，
按“方法、数据、结论、局限”比较，保留论文链接。

安装的技能会自动成为同名斜杠命令，也可能在普通任务与描述匹配时由 Hermes 自动选择。

EXAMPLE A

研究技能

arxiv

用于查找与提取论文。关键是给时间范围、比较维度和输出结构。

EXAMPLE B

项目协作技能

github-pr-workflow

把分支、测试、提交和 PR 的固定流程变成可复用步骤；正式运行前先核对权限。

EXAMPLE C

自建工作流

weekly-competitor-scan

让 Hermes 把刚完成且验证有效的多步流程保存为新技能。

DIY
创建技能自然语言

从一次成功执行中沉淀

复制给 Hermes
把刚才已经验证成功的竞品周报流程保存为技能 `weekly-competitor-scan`。
要求：
1. 明确触发场景、输入与输出；
2. 保留来源核验、发布日期检查和去重步骤；
3. 涉及发布或发送前必须向我确认；
4. 创建后告诉我技能文件位置，并演示一次调用方式。

验收：新会话输入 /weekly-competitor-scan，应能加载完整流程，而不是只复述技能名称。

技能与工具的区别：能用现有工具和命令描述的“做事方法”优先写成 Skill；需要 API、流式数据、二进制处理或运行时集成的能力才更适合做 Tool/Plugin。
07 · PRACTICE DECK

六个可复制练习

按 01 → 06 逐步练习。前两个不要求额外集成，适合第一次使用。

01
只读研究20 分钟

带来源的专题调研

提示词
研究“开源个人 AI Agent”的三种主流路线。
先给研究计划，再使用 web 工具查找官方仓库与官方文档。
比较：部署成本、工具扩展、记忆、远程使用、安全边界。
每个关键结论附直接来源；无法验证的内容明确标注。

验收：来源是官方页面；结论与来源相邻；没有把热度等同于适用性。

02
只读优先本地文件

先审计，再决定是否修改

提示词
只读检查当前项目，不要修改。
找出：入口文件、运行命令、未提交改动、明显风险。
给出 2 个修复方案，分别说明影响范围和验证方法。
等我确认后再编辑。

验收：Hermes 先展示证据和范围，没有在“诊断”阶段擅自改文件。

03
上下文AGENTS.md

让项目规则自动生效

AGENTS.md 示例
# 项目规则
- 修改前先运行测试并记录基线。
- 不覆盖未提交改动。
- 删除、发布、推送前必须确认。
- 完成后报告改动文件、测试结果和剩余风险。

验收：从该目录启动新会话后，Hermes 能主动遵守规则。

04
工具集最小权限

给任务刚好够用的工具

系统终端
hermes chat --toolsets safe -q "研究 Hermes Agent 的技能系统，输出带官方来源的中文摘要"

官方 safe 复合工具集侧重只读研究与媒体生成。涉及本地项目时，可按需选择 web,file,terminal。

验收：先最小权限运行；缺工具时再明确增加，而不是默认开放全部能力。

05
技能复用新会话验证

把周报流程保存成技能

提示词
完成这份周报后，提取其中稳定、可重复的步骤，创建技能 `weekly-brief`。
不要把本周的临时链接和数据写死；保留时间范围、来源质量、去重和输出模板。

验收：技能保存“方法”，不保存一次性的报告内容。

06
自动化Telegram进阶

每天早上自动发送简报

Hermes 会话
每天早上 8 点，搜索过去 24 小时 AI Agent 的重要更新。
只保留 3 条，说明“发生了什么、为什么重要、官方来源”。
使用 weekly-brief 技能，把结果发送到 Telegram。

验收：先确认默认模型、时区、Telegram 白名单和投递目标；再用 /cron 查看任务。

08 · KNOWLEDGE ROUTING

信息应该放在哪里？

放错位置会让上下文臃肿或下次无法复用。用这张表快速判断。

载体存什么例子特点
USER.md你的身份与长期偏好“称呼我为怡哥，中文回复，结论简洁。”跨会话；容量有限，应精炼
MEMORY.md环境事实、项目位置、经验结论“生产部署使用 deploy.yml。”跨会话；是事实快照
Skill可重复的多步做法“每周竞品报告的查找、去重和输出步骤。”按需加载；解决“怎么做”
AGENTS.md项目级规则和验收标准“修改前跑测试；推送前确认。”进入项目时自动发现
SOUL.md长期人格、语气与行为风格“冷静、直接、发现矛盾要指出。”每轮都可能进入上下文，应简短
会话当前任务临时信息本次日志、一次性路径、草稿数据任务结束后通常无需保留
SAVE FACT

让 Hermes 记住

提示词
请记住：这个项目使用 pnpm，发布前必须执行 pnpm test；把它保存为环境事实，不要创建技能。
SAVE METHOD

让 Hermes 保存方法

提示词
这套发布检查以后会重复使用。请把已验证的步骤保存为技能，包含前置条件、失败停止条件和回滚方法。
注意刷新：内置记忆在磁盘上立即写入，但当前会话使用的是启动时快照；新会话才能稳定看到更新后的记忆内容。
09 · AUTOMATION

从手动执行到自动投递

先把手动流程跑通并技能化，再加定时与消息投递。这样更容易定位问题。

CRON

创建与管理定时任务

聊天内
/cron add "0 8 * * *" "使用 weekly-brief 技能生成今日 AI 简报" --skill weekly-brief
/cron

也可以直接用自然语言让 Hermes 创建。任务支持暂停、恢复、编辑、立即运行和删除。

MESSAGING

连接 Telegram

系统终端
hermes gateway setup
hermes gateway

向导中选择 Telegram，填写 Bot Token 与允许访问的数字用户 ID。配置后启动 Gateway，再从手机发送测试消息。

远程入口不是默认公开：务必设置 Telegram 用户白名单。不要公开 Bot Token；一旦泄露，立即在 BotFather 撤销并重新生成。

先跑通手动任务

同一提示词连续执行两次，确认来源、格式和失败处理稳定。

再保存为技能

剔除日期、临时链接等一次性数据，保留可复用步骤。

最后添加定时与投递

明确时区、频率、模型、技能、投递平台和失败时如何通知。

10 · GUARDRAILS

安全边界与排错

真正好用的自动化不是“什么都放开”，而是风险低的部分自动跑，高风险动作停在审批门前。

DO NOT

默认不要开启 --yolo

它会跳过危险命令审批。除非在一次性、隔离、可随时销毁的环境中，并且你完全理解影响，否则保持审批开启。

SECRETS

凭据只进专用配置

API Key、Bot Token 等使用 Hermes 配置向导或 ~/.hermes/.env，不要写进提示词、Skill、AGENTS.md 或 Git 仓库。

CHECKPOINTS

修改前后都要验证

Hermes 会在文件变更前创建检查点。出错时先用 /rollback 查看可恢复点，不要盲目覆盖。

UPDATES

保持版本与文档同步

定期运行 hermes update 获取修复。命令有差异时，以当前版本的 /help 和 hermes --help 为准。

现象先检查处理
找不到 hermes终端是否重启；PATH 是否刷新重开终端，运行 hermes --version；仍失败则按官方安装页排查
模型无法调用hermes status --deep退出聊天后运行 hermes model，重新配置供应商或凭据
技能安装后没出现hermes skills list开始新会话，或安装时使用 --now
工具不可用/tools list运行 hermes tools 配置；确认相应凭据与平台支持
任务越做越偏/status 与当前上下文先 /compress 只保留目标和约束；新任务使用 /new
文件改坏了/rollback检查差异并恢复最近检查点；恢复后重新运行验证
消息机器人不响应Gateway 日志、Token、白名单确保允许用户填写的是数字 ID，并确认 Gateway 正在运行
