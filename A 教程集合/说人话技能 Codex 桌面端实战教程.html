适用场景与使用边界

它是改写和审稿技能，不是事实核查器，也不是“敏感词替换器”。判断标准不是删了多少词，而是改完能不能直接发，同时不失真。

适合

有内容，但写得像模板

  • 聊天回复、协作沟通、评论
  • 进度同步、日报、复盘摘要
  • README、FAQ、release note
  • 公众号、公开帖、观点长文
  • 先标出问题，不直接改稿
不要硬套

任务目标不是风格改写

  • 逐字翻译或必须保留原文风格
  • 仿官方模板、仿特定品牌 voice
  • 主体是代码、日志、配置、命令
  • 需要核实事实、来源或数据真伪
  • 想用它绕过 AI 检测器

先判场景，再决定改多重

同一句“自然一点”，在聊天和技术文档里不是同一种改法。选择场景后查看默认力度、保护重点和 Codex 桌面端输入。

Workflow

六步完成一次可靠改写

原技能有八个执行点。这里把连续判断合并成六步，顺序不变：先锁住不能动的东西，再处理风格。

判场景

确定 chat / status / docs / public-writing 中的主语域。

圈保护项

锁定数字、日期、主体、引用、命令、路径、报错和指标关系。

校准三条轴

问题强度看 Tier；改写力度看 level；能否删句看 scope。

按模式改

先处理套话、黑话、旁白、无源引用和结构问题，词表只兜底。

保真回读

核对信息、术语、语域、责任和 protected spans 是否漂移。

残味审计

仍有模板感才做轻量二遍；默认输出一个推荐版本。

改写力度 level

minimal → standard → aggressive
决定改多重。

＋
编辑范围 scope

structural / bounded / in-place
决定能不能删句、并句、重排。

Guardrails

这些内容先圈住，不能漂

如果一句话只有改坏保护项才能变自然，优先保真。宁可留一点生硬，也不要制造更顺滑的新事实。

Protected spans

数字与时间百分比、版本、区间、单位、时间跨度
主体与归属人名、组织、责任、观点是谁的
技术片段命令、代码、参数、字段、路径、环境变量
运行证据报错、日志、状态码、指标、比较关系
引用边界引号内原文、标题、规范、原话关键词
抽象关系对象类型、动作方向、完成态、适用条件

五个常见误区

  • 把 Tier 当成改写力度
  • 删掉数字后留下一句更泛的话
  • 为了具体，补原文没有的数据
  • 把专业文档一律改成口语
  • 两个 humanizer 连续重改同一稿
记住：清理后的落点必须来自原文。原文只有“提升效率”，不能擅自写成“节省时间”或“降低成本”。
