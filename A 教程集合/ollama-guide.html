Chapter 00

先建立正确预期

Ollama 不是一个“模型”，而是让你在本机下载、运行、管理模型，并通过统一 API 调用它们的运行时。

你将得到

一个可在终端使用、可被脚本调用、可按角色定制的本地 AI 助手。

你不需要

不需要先学机器学习，不需要 Docker；Python 实战不安装任何第三方包。

预计用时

基础路径约 60–90 分钟；完整 API 与工具调用约 2–3 小时。

“本地”不自动等于“永远离线”本地模型的推理发生在你的电脑上；若选择 Ollama 云端模型，提示词会发送到云端处理。本文默认只用本地模型，并给出禁用云功能的方法。

完成标准

01能运行模型
02能定制角色
03能调用 API
04能安全接工具
Chapter 01

它适合什么，不适合什么

很适合

  • 本地写作、总结、分类与信息抽取
  • 私有代码或文档的辅助处理
  • 低成本验证 AI 产品想法
  • 给 PowerShell、Python、桌面工具提供统一 API
  • 无稳定网络时运行已下载模型
  • 比较模型、提示词和参数

不应硬用

  • 弱硬件上强求超大模型的高速体验
  • 需要 7×24 SLA 却没有运维体系
  • 把模型输出直接当作可靠事实或专业结论
  • 未经鉴权和 TLS 就暴露到公网
  • 让模型直接执行付款、删除、群发等高风险动作
  • 忽略模型许可证用于商业发布
需求Ollama 的价值关键代价
隐私与控制本地模型可让输入、输出留在设备内你负责设备、日志和访问控制
快速原型同一套 CLI/API 切换多种模型不同模型能力和提示格式仍有差异
成本可控本地推理没有按 token 的远端调用费硬件、电力、时间不是零成本
离线能力模型下载完成后可断网推理首次下载、更新及云模型仍需网络
Chapter 02

Ollama 的工作流程

记住一条主线：客户端发请求，Ollama 负责模型生命周期，模型在本机完成推理，再把结果流式或一次性返回。

1选择模型确认任务、标签、大小、许可证
2拉取模型ollama pull / run
3加载运行CPU/GPU 与内存参与推理
4发送请求CLI 或 localhost API
5消费结果文本、JSON、向量或工具请求

交互模式

ollama run gemma4 进入对话。适合人直接试模型、改提示词。

服务模式

应用访问 http://localhost:11434/api。适合脚本、工作流和产品原型。

判断问题在哪一层下载失败看网络；启动失败看服务和驱动；输出不好先看模型、提示词与上下文；API 失败看 HTTP 状态、JSON 和端点。
Chapter 03

不要从“最大模型”开始

硬件与模型的关系不是一张万能显存表。量化、上下文、并发、GPU 后端都会改变占用；最可靠的方法是小步选择并实测。

  1. 先定义任务。通用对话、代码、视觉、嵌入或工具调用，需要的能力不同。
  2. 查看官方模型页。确认标签、下载大小、许可证及能力说明。
  3. 选择能稳定运行的最小模型。先完成工作流，再逐步增大。
  4. 用真实任务测试。记录首 token 等待、生成速度、质量和内存占用。
观察项命令/位置如何解释
本地模型ollama ls看名称、标签和磁盘大小
运行模型ollama ps看当前加载、处理器分配和上下文；字段以本机版本为准
模型详情ollama show gemma4看架构、参数、能力和模板
显卡状态nvidia-smi（NVIDIA）看显存占用；没有该命令不代表 Ollama 不可用
上下文越长，内存通常越高不要把模型宣称的最大上下文当成默认实际值。只在任务确实需要时提高 num_ctx，然后重新测内存和速度。
Chapter 04

Windows 安装与验证

官方要求 Windows 10 22H2 或更新版本。推荐使用官方图形安装器：可见、易更新、无需管理员权限。

实验 1｜安装并做三层验证预计 10 分钟
  1. 打开 Ollama 官方 Windows 下载页，下载并运行 OllamaSetup.exe。
  2. 新开 PowerShell。旧终端可能尚未获得新的 PATH。
  3. 依次运行下面三组检查。
PowerShell · 客户端ollama --version
Get-Command ollama | Select-Object Source
PowerShell · 服务Invoke-RestMethod http://localhost:11434/api/version
PowerShell · 真正推理ollama run gemma4 "请只回复：Ollama 已就绪"

可选：PowerShell 一行安装

PowerShellirm https://ollama.com/install.ps1 | iex
管道安装会执行远程脚本只有在确认域名、理解风险并信任脚本时才使用。新手优先选图形安装器。

默认位置与迁移模型盘

程序%LOCALAPPDATA%\Programs\Ollama
配置与模型%USERPROFILE%\.ollama
模型文件%USERPROFILE%\.ollama\models
PowerShell · 设置用户级模型目录[Environment]::SetEnvironmentVariable('OLLAMA_MODELS','D:\OllamaModels','User')

设置后：退出系统托盘里的 Ollama，重新从开始菜单启动，再新开 PowerShell。不要直接搬动正在使用的模型文件。

如何卸载？模型会一起删除吗？
在 Windows“设置 → 应用 → 已安装的应用”卸载 Ollama。若你设置了自定义 OLLAMA_MODELS，官方说明卸载器不会删除该目录；删除模型是独立且可能不可逆的操作，先确认路径和备份需求。

Chapter 06

定制你的 OPC 助手

Modelfile 是模型运行配置的蓝图。我们只改角色和少量参数，不碰不理解的模板。

实验 3｜从基础模型创建专属助手预计 12 分钟

新建一个名为 Modelfile、没有扩展名的 UTF-8 文本文件：

ModelfileFROM gemma4

PARAMETER temperature 0.3
PARAMETER num_ctx 8192

SYSTEM """
你是一个服务于 One-Person Company 的本地 AI 助手。
回答使用简体中文，先给结论，再给可执行步骤。
不确定时明确说“不确定”，不得编造来源。
涉及删除、付款、发布或对外沟通时，必须先请求确认。
"""
PowerShellSet-Location 你的Modelfile所在目录
ollama create opc-assistant -f .\Modelfile
ollama run opc-assistant "帮我把今天的三项工作排优先级"
指令用途新手建议
FROM基础模型或本地 GGUF/Safetensors必填；先用官方库模型
SYSTEM固定角色与行为边界写清输出语言、目标和禁区
PARAMETER温度、上下文等一次只改一个并测试
MESSAGE示例历史消息用于稳定风格，避免堆太多
TEMPLATE底层提示模板不理解模型格式时不要改
ADAPTER应用 (Q)LoRA 适配器属于进阶导入场景
Chapter 07

从对话框走向 API

默认 API 基址是 http://localhost:11434/api。单轮生成用 /generate，多轮对话优先用 /chat，向量化用 /embed。

端点输入核心适用
POST /api/generatemodel + prompt单轮补全、简单生成
POST /api/chatmodel + messages多轮对话、工具、结构化输出
POST /api/embedmodel + input语义检索、聚类、RAG
GET /api/tags无列出本地模型
GET /api/ps无列出运行模型
实验 4｜在 PowerShell 发出第一条 API 请求预计 6 分钟
PowerShell$body = @{
  model = 'opc-assistant'
  messages = @(
    @{ role = 'user'; content = '给我一个 15 分钟日计划模板' }
  )
  stream = $false
} | ConvertTo-Json -Depth 6

$result = Invoke-RestMethod `
  -Uri 'http://localhost:11434/api/chat' `
  -Method Post `
  -ContentType 'application/json; charset=utf-8' `
  -Body $body

$result.message.content

流式与非流式

stream: false

一次返回完整 JSON。最适合新手、自动化脚本和结构化输出。

stream: true

默认行为，以换行分隔 JSON 片段；更快看到首段内容，但客户端必须逐行解析和拼接。

指标单位响应中的 total_duration、load_duration 等时长以纳秒计；生成速度可近似用 eval_count ÷ (eval_duration / 1e9) 计算 tokens/s。
Chapter 08

PowerShell 多轮助手

实验 5｜保留上下文的终端助手预计 15 分钟

把下面内容保存为 opc-chat.ps1。它只使用 PowerShell 内置能力：

PowerShell$model = 'opc-assistant'
$messages = [System.Collections.ArrayList]::new()

Write-Host 'OPC 助手已启动。输入 /bye 退出。' -ForegroundColor Green
while ($true) {
  $inputText = Read-Host '你'
  if ($inputText -eq '/bye') { break }
  if ([string]::IsNullOrWhiteSpace($inputText)) { continue }

  [void]$messages.Add(@{ role = 'user'; content = $inputText })
  $payload = @{
    model = $model
    messages = $messages
    stream = $false
  } | ConvertTo-Json -Depth 10

  try {
    $response = Invoke-RestMethod `
      -Uri 'http://localhost:11434/api/chat' `
      -Method Post -ContentType 'application/json; charset=utf-8' `
      -Body $payload -TimeoutSec 300
    $answer = $response.message.content
    Write-Host "助手：$answer" -ForegroundColor Cyan
    [void]$messages.Add(@{ role = 'assistant'; content = $answer })
  } catch {
    Write-Warning "请求失败：$($_.Exception.Message)"
    [void]$messages.RemoveAt($messages.Count - 1)
  }
}
PowerShell · 运行powershell -ExecutionPolicy Bypass -File .\opc-chat.ps1
历史不会凭空保留/api/chat 是由客户端把 messages 再次发送。对话越长，输入 token、延迟和内存压力通常越高；生产应用要做截断、摘要或检索。
Chapter 09

零依赖 Python 助手

官方有 Python 包，但这个实验刻意只用标准库，让你看清 HTTP 与 JSON 的本质，也满足离线单文件教程“不依赖外部模块”的目标。

实验 6｜构建可复用的 API 客户端预计 15 分钟
Python 3import json
import urllib.error
import urllib.request

API = "http://localhost:11434/api/chat"
MODEL = "opc-assistant"

def chat(messages):
    payload = json.dumps({
        "model": MODEL,
        "messages": messages,
        "stream": False,
        "keep_alive": "5m",
    }, ensure_ascii=False).encode("utf-8")
    request = urllib.request.Request(
        API,
        data=payload,
        headers={"Content-Type": "application/json; charset=utf-8"},
        method="POST",
    )
    with urllib.request.urlopen(request, timeout=300) as response:
        return json.load(response)

messages = []
print("OPC 助手已启动。输入 /bye 退出。")
while True:
    text = input("你：").strip()
    if text == "/bye":
        break
    if not text:
        continue
    messages.append({"role": "user", "content": text})
    try:
        result = chat(messages)
        answer = result["message"]["content"]
        print("助手：", answer)
        messages.append({"role": "assistant", "content": answer})
    except urllib.error.HTTPError as exc:
        detail = exc.read().decode("utf-8", errors="replace")
        print(f"HTTP {exc.code}: {detail}")
        messages.pop()
    except urllib.error.URLError as exc:
        print("无法连接 Ollama：", exc.reason)
        messages.pop()
如果你愿意安装官方 SDK可使用官方 ollama-python，它能简化流式、工具与类型处理。但理解上面的标准库版本，会让排错更容易。
Chapter 10

让输出成为可用数据

自由文本适合人读，JSON Schema 适合程序接。结构化输出用于分类、抽取、表单生成和自动化衔接。

实验 7｜把自然语言任务变成 JSON预计 10 分钟
PowerShell$schema = @{
  type = 'object'
  properties = @{
    goal = @{ type = 'string' }
    priority = @{ type = 'string'; enum = @('高','中','低') }
    next_actions = @{ type = 'array'; items = @{ type = 'string' } }
  }
  required = @('goal','priority','next_actions')
}

$body = @{
  model = 'opc-assistant'
  messages = @(@{
    role = 'user'
    content = '分析任务：周五前发布产品落地页。严格按给定 schema 输出。'
  })
  format = $schema
  stream = $false
} | ConvertTo-Json -Depth 12

$response = Invoke-RestMethod `
  -Uri 'http://localhost:11434/api/chat' `
  -Method Post -ContentType 'application/json; charset=utf-8' -Body $body

$data = $response.message.content | ConvertFrom-Json
$data | Format-List
Schema 约束不等于业务正确它提高格式可靠性，但模型仍可能填入错误事实。程序还要验证枚举、长度、日期、ID 和业务规则。
Chapter 11

让模型请求工具，而不是直接掌权

工具调用的核心是一个受控循环。模型只能提出“想调用什么”，真正执行权始终在你的程序。

1声明工具名称、描述、JSON 参数
2模型选择返回 tool_calls
3程序验证白名单、类型、范围、权限
4执行工具你的代码真正运行
5回传结果role: tool 后再次请求
实验 8｜安全的本地时间工具预计 20 分钟

这是关键请求骨架；完整应用应再加入工具名白名单、参数 schema 校验、超时与审计日志。

JSON · POST /api/chat{
  "model": "opc-assistant",
  "messages": [
    {"role": "user", "content": "现在几点？"}
  ],
  "stream": false,
  "tools": [{
    "type": "function",
    "function": {
      "name": "get_local_time",
      "description": "读取本机当前时间，不接受参数",
      "parameters": {"type": "object", "properties": {}}
    }
  }]
}
  1. 检查响应中的 message.tool_calls，只接受精确名称 get_local_time。
  2. 由程序执行 Get-Date -Format o 或 Python datetime.now().isoformat()。
  3. 把结果追加为 {"role":"tool","tool_name":"get_local_time","content":"..."}。
  4. 连同完整消息历史再次请求 /api/chat，获得自然语言回答。

绝不能直接照做

不要把模型返回的字符串拼进 Invoke-Expression、Shell、SQL 或文件路径；不要让模型绕过确认执行删除、付款、发布和对外通信。把模型输出视为不可信输入。

Chapter 12

性能、安全与排错

先测，再优化

现象可能方向优先动作
第一次很慢，随后变快首次加载模型查看 load_duration；按需使用 keep_alive
生成一直慢模型过大、CPU 卸载、上下文过长ollama ps，换小模型，缩短上下文
内存不足模型/上下文/并发超预算停掉其他模型，降低尺寸和 num_ctx
长对话变差历史噪声或上下文截断摘要旧历史，保留关键事实，必要时用检索

安全底线

默认保持本机绑定

默认 127.0.0.1:11434 只允许本机访问，最适合个人使用。

不要裸露公网

OLLAMA_HOST=0.0.0.0:11434 会扩大攻击面。需要网络访问时应加认证、TLS、防火墙和反向代理。

PowerShell · 强制关闭云功能[Environment]::SetEnvironmentVariable('OLLAMA_NO_CLOUD','1','User')

设置后退出托盘中的 Ollama，再从开始菜单重启。此设置会停用云端模型和依赖云能力的功能。

六步诊断法

  1. 客户端：ollama --version 是否可用？
  2. 服务：Invoke-RestMethod http://localhost:11434/api/version 是否响应？
  3. 模型：ollama ls 是否包含请求的准确标签？
  4. 状态：ollama ps 是否显示模型和处理器分配？
  5. 资源：磁盘、内存、显存、驱动是否足够？
  6. 日志：查看 %LOCALAPPDATA%\Ollama，再对照官方排错页。
“ollama 不是内部或外部命令”
关闭并重新打开终端；检查 Get-Command ollama。默认程序目录是 %LOCALAPPDATA%\Programs\Ollama。若文件存在但 PATH 未更新，退出登录或重启 Ollama/终端后再试。
API 报连接被拒绝
桌面应用可能未启动。先从开始菜单启动 Ollama；确认托盘图标，再调用 /api/version。若你手动运行服务，检查是否已有进程占用 11434。
模型下载慢或失败
检查磁盘、网络、证书和代理。官方建议模型拉取使用 HTTPS_PROXY；避免设置 HTTP_PROXY，它可能干扰客户端与本地服务通信。
模型回答乱码或 JSON 解析失败
PowerShell 请求设置 application/json; charset=utf-8；文件保存为 UTF-8。结构化输出应设置 stream:false 并使用 JSON Schema，随后仍做业务校验。
GPU 没有被使用
先查看 ollama ps，再核对官方硬件支持页与显卡驱动。不要仅凭任务管理器某一个图表下结论；不同后端和共享显存的表现不同。

下一步学习顺序

  1. 用 10 条真实任务比较两个小模型，不凭榜单选型。
  2. 为提示词和结构化 schema 建立固定测试样本。
  3. 学习 Embeddings：索引和查询始终使用同一个嵌入模型。
