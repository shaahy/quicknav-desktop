02 · SKILL STACK

三层读取，顺序不能反。

OpenMontage 的关键不是“找到一个万能 skill”，而是用不同层分别回答工具、阶段和 provider 三种问题。

L1 · REGISTRY / TOOL CONTRACT

先发现真实能力

“现在有什么？”

查询 capability、provider、可用状态、运行方式、fallback、费用线索和相关 skills。动态信息以本机 registry 为准。

registry.capability_catalog()
registry.provider_catalog()
L2 · PIPELINE DIRECTOR

再读取阶段规则

“本阶段怎么做？”

05 · BRANCHES

阻塞不是授权你悄悄换路。

异常处理的核心是保持决策可见：说清失败、给出选项、推荐一条，然后停下来。

BLOCKED / HOLD

工具、权限或质量失败

  1. 说明尝试了什么
  2. 判断 auth / provider / tool bug / 质量问题
  3. 列出选项、取舍和推荐
  4. 等待批准，不自动替换
provider/model/runtime 不静默变更
REWORK / RETURN

只回到指定节点

  1. 锁定返工 scene 或 artifact
  2. 保留其他已批准内容
  3. 先说明下游影响
  4. 重新 review 与 checkpoint
只返工 scene 04，不重做整片
RESUME / CHECKPOINT

从断点继续，不从头再来

  1. 读取 checkpoint 状态
  2. 确认 completed / awaiting_human
  3. 定位 get_next_stage
  4. 汇报恢复点后继续
checkpoint 是恢复协议，不只是日志
06 · ARTIFACT CONTRACT

每阶段只交付一个权威合同。

canonical artifact 是下一阶段的输入。随口聊天不能替代正式产物，修改上游时也要检查下游是否失效。

research研究与事实边界主题范围、来源、素材约束。
proposal生产方案delivery promise、工具路线、成本和 runtime。
script正式脚本旁白、节奏、字幕与时长意图。
scene_plan逐镜合同镜头顺序、时长、资产需求与画面目标。
asset_manifest素材清单来源、文件、model/tool 元数据和镜头关联。
edit编辑结果已批准资产的画面、音频和字幕组合。
checkpoint_*.json阶段状态completed、failed、awaiting_human 或 in_progress。
final标准成片projects/<project>/renders/final.mp4
07 · COPY DECK

六条 Codex 控制提示词。

这些提示词控制“怎样生产”，不是替你写创意内容。点击即可复制。

定位当前阶段
先读取当前项目 checkpoint，报告：pipeline、已完成阶段、下一阶段、对应 director skill、预期 canonical artifact、review focus 和是否需要人工批准。报告后停下。
完整能力审计
运行 mandatory preflight。不要依赖旧文档或记忆：从 registry 报告各 capability 的可用 provider、状态、runtime、fallback、相关 skills 和已知成本；再给出与你推荐 pipeline 相符的生产路线。
批准当前阶段
我批准当前 canonical artifact。记录 checkpoint，然后只进入下一阶段；开始前先读取该阶段 director skill，并告诉我本阶段产物、工具范围、质量门和下一个停止点。
先样本后批量
先制作能代表最终质量的最小样本，覆盖最难镜头和正式声音路线。提交样本、实际工具/provider/model、成本与 review 结果后 HOLD，不进入批量生成。
只返工指定内容
只返工我指定的 scene 或 artifact，保留其他已批准内容。执行前先列出受影响的下游文件、预算变化和需要重新通过的 review/checkpoint。
阻止静默替换
不要静默更换 provider、model、render runtime、旁白、音乐或视频路线。遇到阻塞时说明尝试、失败类型、所有可选方案、取舍与推荐，然后等待我批准。
08 · RED LINES

六条最容易被跳过的生产纪律。

如果 Codex 的行动违背这些规则，先停下来纠正流程，再继续生产。

不绕过 pipeline

不要临时写脚本直调 API，也不要跳过 preflight、review 或 checkpoint。

不跳过 director skill

每个 stage 动手前都要读取相应 director；不同阶段的成功标准不同。

不跳过 Layer 3

生成工具声明的 provider skill 是必读项，不能用通用提示词替代。

不隐藏降级路线

still-led、provider 替换、移除音乐或旁白都属于需要告知的重大变化。

不在批准前批量生成

先提交方案、成本和代表性样本，确认之后才扩大调用。

不把 Beta 当成成熟路线

Beta pipeline 可以选，但必须如实说明粗糙边缘和额外验证成本。
