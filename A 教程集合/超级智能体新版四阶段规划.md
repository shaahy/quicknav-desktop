# 超级智能体新版四阶段规划

> 版本日期：2026-09-02  
> 文档用途：战略对齐、老板汇报、项目路演、后续阶段 Brief 与 PRD 输入  
> 阶段路径：**数字分身 → 智能伙伴 → 持续在场 → 全局调度**

## 一句话愿景

**超级智能体以属于用户的数字分身为起点，通过 MCP 获得现实行动能力，再借助视觉与可穿戴设备持续在场；最终，超级元梦在持续满足每个个体个性化需求的基础上，把无数个人智能伙伴、组织与现实服务连接成一个全局协作和调度网络。**

## 四阶段进化主线

> **代表我 → 替我办事 → 与我同在 → 全局调度**

这不是四个相互割裂的产品，而是同一个个人智能体持续获得新能力的成长过程：

1. **数字分身**解决“它是不是我、懂不懂我、能不能代表我”；
2. **智能伙伴**解决“它能不能连接现实服务，真正把事情办成”；
3. **持续在场**解决“它能不能看见我的现场，在需要时及时出现”；
4. **全局调度**解决“如何先满足每个个体的个性化需求，再让无数智能伙伴跨人、跨组织、跨服务共同完成更大的事情”。

## 四阶段总览

| 阶段 | 产品名称 | 阶段主题 | 核心跃迁 | 主要载体 | 阶段完成标志 |
|---|---|---|---|---|---|
| 第一阶段 | 超级智能体·数字分身 | 代表我 | 从通用 AI 跃迁为可持续维护、属于用户的个人数字身份 | 数字人管理中台、本人 Web 管理工作台、本人独立对话式维护 H5、关系对象 Web/H5 | 每个人拥有一个像自己、懂自己、可在授权范围内代表自己的数字身份 |
| 第二阶段 | 超级智能体·智能伙伴 | 替我办事 | 从能够表达和代理，跃迁为能够连接现实服务、完成真实任务 | 第一阶段产品界面、MCP 服务网络 | 用户提出目标后，智能伙伴能够调用服务、处理过程并交付可验证结果 |
| 第三阶段 | 超级智能体·持续在场 | 与我同在 | 从等待用户发起，跃迁为看见现场、理解处境、持续陪伴 | 带视觉能力的智能耳机及其他可穿戴设备 | 智能伙伴能持续理解用户所见所闻，在恰当时机提醒、判断并行动 |
| 第四阶段 | 超级元梦·全局调度 | 全局调度：跨智能体的全局协作系统 | 从满足单个用户，跃迁为先形成每个个体的个性化方案，再实现跨智能体、跨组织、跨服务的全局协作 | 超级元梦云端大脑、个人智能体网络、组织与现实服务网络 | 每个个体都获得符合自身需求与边界的结果，同时实现整体资源的高效协作与调度 |

# 第一阶段：数字分身

## 阶段主题

**代表我**

## 阶段定位

建立用户可持续拥有、训练、校准、维护和授权的个人数字身份。数字人管理中台创建用户账户时，系统同步自动创建一个不可单独删除的默认数字人；默认数字人创建即完成，除自动生成名称外其他内容可以为空，由用户本人逐步维护。

用户不仅可以在 Web 管理工作台中进行结构化管理，还可以通过独立的对话式维护 H5 与自己的数字分身对话，随时查询、补充、配置和修改名称、资料、知识、人格、使命、关系、边界、记忆、授权、形象与声音。该 H5 是面向已认证用户本人的独立应用，不是 Web 工作台的附属聊天组件，也不是关系对象互动入口；各本人维护入口读写同一权威配置。

人格与使命不强制设置独立维护页面，关系类型详情也不是唯一配置入口。普通配置变更在展示清晰影响范围并由本人确认后生效；删除、发布、授权扩大、重大承诺等事项继续遵循各自专项规则。

第一阶段不是一个等待后续升级的临时聊天机器人，而是整个四阶段蓝图的身份与个人大脑底座。

## 两个产品域、四个应用界面

1. **用户本人 Web 管理工作台**：承担结构化创建、查看、编辑、确认、发布和治理。
2. **用户本人独立对话式维护 H5**：让已认证用户通过与自己的数字分身对话，低负担地持续查询和维护同一权威配置。
3. **关系对象互动 Web/H5**：让关系对象与数字分身透明互动，并管理自身数据与主体权利；不承担用户本人的数字分身维护。
4. **超级管理端／数字人管理中台**：创建和治理用户账户、功能、配额与平台规则，并随账户自动生成默认数字人；不代用户填写、编辑、确认、发布或维护数字人内容。

## 三个核心引擎

### 1. 数字身份复刻引擎

复刻用户的形象、声音、表达习惯、价值判断、身份角色和不同场景下的呈现方式，形成可被本人持续校准的数字身份。

### 2. 长期记忆与人格引擎

理解并组织用户的人生经历、人物关系、价值观、目标、使命、情绪与承诺，让数字分身不是只记住资料，而是逐渐理解“我是谁、我为什么这样判断”。

### 3. 授权代理与治理引擎

由用户设置披露范围、代理权限、行动边界和升级条件。低风险事务可以自主完成，涉及重大决定、现实责任和关键承诺时交还本人。

## 六项基础能力

- 身份复刻与人格编排
- 长期记忆与人生理解
- 场景人格与披露边界
- 使命驱动与主动代理
- 社交存在与关系连续性
- 同步、授权与可信治理

## 用户端价值闭环

> **自动获得数字分身 → 创建与校准 → 对话式持续维护 → 关系连续 → 受控代理 → 经历汇流 → 持续成长**

1. **创建与校准**：用户随账户自动获得默认数字人，并逐步完善形象、声音、资料、人格、使命、关系与边界。
2. **对话式持续维护**：用户通过独立 H5 与自己的数字分身对话，低负担地查询、补充和修改数字分身；变更在影响范围清晰可见并由本人确认后进入同一权威状态。
3. **关系连续**：数字分身面对不同关系对象延续上下文，同时避免串用关系记忆或制造虚假亲密。
4. **受控代理**：数字分身只在预授权范围内处理低风险事务，重大决定、现实责任和关键承诺交回本人。
5. **经历汇流**：用户亲历与数字分身代理经历持续同步、审阅和校准，沉淀为连续的个人数字身份。

## 两个代表场景

1. **诞生我的数字分身**：账户创建后自动获得默认数字人，再由本人训练、校准并发布自己的数字身份。
2. **替我持续陪伴粉丝**：数字分身以明确身份与粉丝互动，延续双方的关系记忆，让一次问答发展为长期陪伴；涉及私密信息、重大承诺或超出授权的问题时拒绝、降级或交回本人。

## 阶段完成标志

> **让每个人自动获得一个属于自己的默认数字人，能够通过独立 H5 与它对话并持续维护；Web 与 H5 始终呈现同一权威状态，数字分身最终成长为像自己、懂自己，并能在授权范围内代表自己的数字身份。**

# 第二阶段：智能伙伴

## 阶段主题

**替我办事**

## 阶段定位

第二阶段只建设 MCP 连接和行动能力，让数字分身进入现实服务系统，从“能够表达我、陪伴关系对象、完成有限代理”，升级为“能够理解目标、调用工具、处理过程并交付结果”的数字智能伙伴。

用户不需要了解每个服务的入口和操作步骤，只需要表达目标。智能伙伴结合用户的身份、记忆、偏好、日程、关系和授权边界，选择合适的 MCP，完成单服务调用或多服务协同，并用清晰回执交付结果。

本阶段的核心价值不是连接了多少接口，而是用户能否把一件真实事务放心交给智能伙伴，并收到可验证的现实结果。

## 核心跃迁

> **从“它能代表我说话”，跃迁为“它能替我把事情办成”。**

## 四个核心引擎

### 1. MCP 能力接入引擎

将办公、沟通、日程、地图、交通、票务、酒店、餐饮、电商、支付、医疗、智能家居等现实服务封装为可发现、可调用、可治理的能力。

### 2. 目标理解与任务规划引擎

把用户的一句话目标转化为清楚的任务计划，识别必要条件、执行顺序、依赖关系、成功标准和需要本人决定的关键节点。

### 3. 多服务行动编排引擎

选择一个或多个 MCP 执行任务，处理参数传递、状态衔接、等待、重试、替代服务和异常续办，直到形成完整结果。

### 4. 授权、回执与恢复引擎

在用户授权范围内自主执行；涉及超额消费、敏感披露、重大决定和不可逆承诺时请求确认。每次行动都留下原因、过程、服务响应和最终结果。

## 核心能力

- MCP 服务发现、接入、认证与能力目录
- 自然语言目标理解与任务拆解
- 单 MCP 调用与多 MCP 工作流编排
- 个人记忆、偏好、关系和日程的上下文调用
- 预授权、额度、敏感操作和越界确认
- 服务失败识别、替代方案、重试与断点续办
- 行动状态追踪、结果回执与用户接管
- 执行结果写回个人大脑并形成新的偏好依据

## 价值闭环

> **表达目标 → 理解个人上下文 → 拆解任务 → 选择并编排 MCP → 按授权执行 → 处理异常 → 交付真实结果 → 写回个人大脑**

这一闭环必须同时满足三个结果：

1. **事情办成**：不是给出教程或建议，而是形成真实服务结果。
2. **过程可控**：用户随时知道正在做什么、为何这样做，并能暂停或接管。
3. **越用越懂**：执行结果持续沉淀，下一次减少重复说明和操作。

## 两个代表场景

### 场景 1：我只说一句，它把整件事办完

用户只表达目标。智能伙伴自动拆解任务、编排多个 MCP、处理依赖和异常，在授权范围内持续推进；涉及支付、重大承诺或不可逆操作时交回本人，最终交付完整结果与可追溯回执。

### 场景 2：一句话，它把我送到目的地

用户只需说明目的地和时间。智能伙伴结合日程、位置、预算与出行偏好，调用地图、交通、票务、打车和日历等 MCP，完成路线规划、预订、通知与动态调整，并持续交付执行结果。

## 阶段完成标志

> **用户只需说清目标，智能伙伴就能在授权范围内连接现实服务、完成任务、处理异常并交付可验证结果。数字分身由此真正成为能办事的数字智能伙伴。**

# 第三阶段：持续在场

## 阶段主题

**与我同在**

## 阶段定位

在智能伙伴已经具备 MCP 行动力的基础上，加入视觉能力和持续在场的可穿戴设备。智能伙伴通过摄像头、麦克风、扬声器、位置及环境传感器共享用户的第一人称视角，理解用户正在看什么、听什么、面对什么，以及当前情境对用户意味着什么。

用户不再需要每次打开应用、整理背景、重新描述问题。智能伙伴能够保持连续上下文，在合适时机主动提醒、辅助判断，并调用第二阶段已经建立的 MCP 能力完成现实行动。

本阶段的核心价值不是“设备一直开着”，而是智能伙伴能够长期在场、低打扰地理解现场，只在真正有价值的时刻出现。

## 核心跃迁

> **从“等我告诉它要做什么”，跃迁为“它看见我正在经历什么，并在需要时及时出现”。**

## 四个核心引擎

### 1. 视觉与多模态感知引擎

识别人、物体、文字、空间、动作、事件和环境变化，并结合声音、位置和设备状态建立对现实现场的即时理解。

### 2. 第一人称连续情境引擎

通过可穿戴设备保持跨时间、跨地点、跨任务的连续上下文，知道用户从哪里来、正在做什么、下一步可能发生什么。

### 3. 现实记忆融合与判断引擎

把现场信息与用户的长期记忆、人物关系、偏好、承诺、目标和健康状态关联，判断当前事情对这个用户的真实意义。

### 4. 实时陪伴与行动引擎

在耳边提供提醒、判断、风险预警和决策建议；需要行动时调用 MCP，完成沟通、记录、导航、预约、调整计划等现实任务。

## 核心能力

- 人物、物体、文字、空间与事件的视觉理解
- 视觉、听觉、位置及环境信息融合
- 可穿戴设备上的低延迟语音交互
- 第一人称连续上下文与短期情境记忆
- 现场信息与长期记忆、关系、目标的融合
- 关键变化检测、主动提醒与风险预警
- 现场判断与 MCP 行动力的实时联动
- 重要现实经历的自动整理、确认与长期写回
- 低打扰、可暂停、可见状态和隐私控制

## 价值闭环

> **持续感知所见所闻 → 理解人物、物体与环境 → 关联个人记忆和当前任务 → 判断用户此刻需要什么 → 实时提醒或调用 MCP 行动 → 把现场经历写回个人大脑**

这一闭环带来三层价值：

1. **不用重复描述现场**：智能伙伴已经拥有足够的情境。
2. **重要时刻不会错过**：变化、风险和承诺能够被及时发现。
3. **帮助发生在行动当下**：建议和执行不再脱离用户正在经历的现实。

## 两个代表场景

### 场景 1：再次见面，它替我记得你

智能伙伴认出对方，在耳边提示姓名、关系、共同经历和未完成承诺；需要记录的新信息由用户确认后进入关系记忆。

### 场景 2：会议中的第二大脑

会前调取背景，现场理解人物、议题和承诺，在关键节点提供判断；会后自动生成纪要、任务、邮件和跟进计划。

## 阶段完成标志

> **智能伙伴能够通过视觉与可穿戴设备持续理解用户所见、所闻和所处情境，在关键时刻主动提醒、辅助判断、调用现实服务，并把共同经历沉淀为连续的人生记忆。**

# 第四阶段：全局调度

## 阶段主题

**全局调度：跨智能体的全局协作系统**

## 阶段定位

超级元梦从服务单个用户的个人智能伙伴之上，成长为连接个人智能体、组织智能体与现实服务的全局协作和调度大脑。

每个人仍然拥有自己的数字分身和智能伙伴。超级元梦首先通过每个人的智能伙伴，理解其独特的身份、目标、偏好、时间、资源、关系、处境与授权边界，为每个个体形成符合自身需求的个性化方案；只有在个体需求被识别、个体利益被保护、个体方案可以成立的基础上，超级元梦才进一步发现跨人关系与全局机会，组织各方智能体协商，并调度现实服务完成共同目标。

本阶段的核心价值不是用一个统一方案安排所有人，也不是为了整体效率牺牲个体差异。它要实现的是：**先让每个人获得适合自己的方案，再把这些个性化方案组织成能够共同成立的全局方案。**最终，全局调度既提高整体协作效率，也让每个个体获得更符合自身需求的结果。

## 核心原则

> **个体价值先闭环，全局协作再发生。**

全局调度必须同时成立两个结果：

1. **对每个个体成立**：每个人的个性化需求、利益、时间、偏好和边界都得到尊重，并获得清晰可执行的个人方案。
2. **对整体协作成立**：在多个个人方案都可接受的基础上，超级元梦寻找共同交集，协调资源并形成整体最优的协作结果。

## 核心跃迁

> **从“一个智能伙伴满足一个人的个性化需求”，跃迁为“超级元梦在满足每个个体的基础上，让所有智能伙伴共同办成更大的事”。**

## 四个核心引擎

### 1. 个体需求与能力理解引擎

通过每个人的智能伙伴，理解不同个体的身份、目标、偏好、关系、时间、位置、资源、处境与授权边界，形成持续变化的个体需求和能力模型。

### 2. 个性化方案生成引擎

先以每个个体为单位形成符合其需求、利益和边界的可执行方案，明确哪些条件必须满足、哪些条件可以协商、哪些条件不能被全局目标覆盖。

### 3. 多智能体协作与机会发现引擎

在各方个性化方案可以成立的基础上，发现尚未被主动表达的合作、匹配和资源互补；由各方个人智能伙伴保护自身用户的隐私、利益和边界，在有限披露条件下完成方案比较、利益协调和共同确认。

### 4. 全局资源调度引擎

把多个可接受的个性化方案组合成全局可执行计划，调用 MCP 和组织能力，协调交通、餐饮、场馆、酒店、医疗、办公、供应链及城市服务等现实资源；调度结果再转化为适合每个个体的差异化行动。

## 核心能力

- 每个个体的身份、目标、偏好、处境和边界理解
- 面向个体的个性化需求建模与方案生成
- 个体方案的必须条件、可协商条件与不可让渡边界
- 跨用户、跨组织的意图、能力和资源图谱
- 隐性需求识别、机会发现与供需匹配
- 多智能体身份验证、发现和协作协议
- 有限披露、多方授权与利益边界保护
- 多个个性化方案的交集计算、协商与共同确认
- 群体趋势预测、资源缺口识别与提前调度
- 跨服务、跨组织工作流编排与动态重排
- 个体需求满足度与全局协作效率的联合优化
- 差异化结果分发：同一次全局调度落到每个人不同的具体行动
- 协作结果写回各方关系、记忆和全局知识网络

## 价值闭环

> **理解每个个体的个性化需求 → 为每个人形成可接受的个人方案 → 寻找多个个人方案的协作交集 → 调动各方智能伙伴协商 → 形成兼顾个体与整体的全局方案 → 编排现实服务共同执行 → 将差异化结果返回每个个体 → 沉淀新的关系与协作网络**

这是一个“个体闭环在前、全局闭环在后”的双层价值闭环：

1. **每个人先被真正理解和满足**：全局系统不是把人抽象成统一需求，而是先形成符合每个人实际情况的个性化方案。
2. **个性化方案能够共同成立**：超级元梦寻找个人方案之间的交集，让各方在不牺牲关键利益和边界的前提下完成协作。
3. **个体价值与全局效率同时提高**：通过整体资源优化，让每个人获得比单独行动更好的结果，同时降低全社会的沟通、等待和资源浪费。

## 两个代表场景

### 场景 1：发现一场还没有被任何人说出口的合作

超级元梦从不同人的目标、资源、能力和计划中识别互补机会，先分别判断这场合作能为每一方带来什么价值、需要承担什么成本、是否符合各自边界，再由各自智能伙伴进行有限披露和前置协商。

### 场景 2：城市级变化发生前，超级元梦已经开始调度

超级元梦识别群体需求变化，预测交通、住宿、餐饮、医疗或公共服务压力。它不是向所有人发布同一个安排，而是根据每个人的位置、健康、家庭、行程、风险和偏好生成差异化方案，再以全部个体方案的汇总需求为依据，提前协调服务供给和城市资源。

## 阶段完成标志

> **超级元梦能够先理解并满足每个个体的个性化需求，再发现跨人、跨组织、跨服务的协作机会，组织多方智能伙伴协商并调度现实资源；最终既形成整体最优的协作结果，也让每个人获得符合自身需求、利益和边界的具体行动方案。**

# 贯穿四阶段的共同底座

## 1. 用户身份与个人大脑

身份、人格、长期记忆、关系、使命、偏好、人生经历和授权边界始终属于用户，是后续所有能力的基础。

## 2. 授权与用户最终控制

- 范围内自主执行，减少无意义确认；
- 越过金额、披露、责任和重大承诺边界时请求本人确认；
- 用户可以查看、暂停、撤销、接管或终止行动；
- 全局调度不能取代每个用户对自身智能伙伴的最终控制，也不能为了整体目标牺牲个体的核心需求、利益与边界。

## 3. 可追溯行动与真实回执

每次行动都应说明使用了什么信息、为何采取行动、调用了什么服务、产生了什么结果、由谁确认，以及失败后如何恢复。

## 4. 连续成长

互动、行动和现实经历在本人可见、可纠正的前提下写回个人大脑，使智能伙伴逐渐减少重复询问，并更准确地理解用户。

# 最终蓝图

四个阶段共同完成一次从个人到世界的能力扩展：

1. **数字分身**让 AI 拥有“我的身份”；
2. **智能伙伴**让个人数字身份拥有“现实行动力”；
3. **持续在场**让智能伙伴拥有“对现实现场的连续理解”；
4. **全局调度**让无数智能伙伴在“满足每个个体个性化需求”的基础上，拥有共同协作和调度世界的能力。

最终，用户获得的不只是一个聊天工具，而是一个属于自己、理解自己、能够办事、持续在场的智能伙伴；超级元梦则先保障每个个体都获得符合自身需求的方案，再让所有个人智能伙伴、组织和现实服务形成一个能够发现机会、协调行动并持续进化的全局协作与调度大脑。
