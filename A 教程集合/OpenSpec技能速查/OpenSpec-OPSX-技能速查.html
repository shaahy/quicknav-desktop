我现在该用哪个？

按你眼下的问题直接跳到技能。

想法还模糊/opsx:explore

调查代码、比较选项，不创建变更产物。

 需求已经明确/opsx:propose

一次生成完整规划产物，快速进入实施。

 复杂变更要逐件审/opsx:new → continue

先建骨架，再逐个生成与审阅产物。

 计划需要改口径/opsx:update

只修订规划，并保持各产物互相一致。

 准备开始写代码/opsx:apply

按 tasks.md 实现、测试并勾选进度。

 担心实现与规格漂移/opsx:verify

查完整性、正确性与一致性。

 长期变更先同步规格/opsx:sync

把 delta 合并进主规格，但不归档。

 单个变更要收尾/opsx:archive

检查、同步并保存审计历史。

 并行变更多个收尾/opsx:bulk-archive

识别冲突并按创建顺序批量归档。

 第一次使用 OpenSpec/opsx:onboard

用真实代码完成一次带讲解的全流程。

最常用的完整路径

快速路径；过程中可随时插入 update、verify 或 sync。

1. 探索/opsx:explore
2. 规划/opsx:propose
3. 实施/opsx:apply
4. 验证/opsx:verify
5. 同步/opsx:sync（可选）
6. 归档/opsx:archive

CLI 管理命令附录

在终端执行，负责安装、状态、校验和配置；不要与聊天中的 OPSX 技能混用。

高频 CLI

npm install -g @fission-ai/openspec@latest全局安装或升级 OpenSpec。
openspec init初始化目录结构和 AI 工具集成；要求 Node.js 20.19.0+。
openspec config profile选择 Core 或自定义工作流组合。
openspec update升级 CLI 后重新生成技能和命令文件。
openspec list列出活动变更；加 --specs 查看规格。
openspec status --change <name>查看产物依赖、完成度和阻塞项。
openspec show <item>查看指定 change 或 spec 的详情。
openspec validate --all --strict严格校验所有变更与规格结构。

不同 AI 工具的调用写法

  • Claude Code：/opsx:propose、/opsx:apply
  • Cursor / Windsurf / Copilot IDE：/opsx-propose、/opsx-apply
  • Codex：通过 .codex/skills/openspec-* 中生成的技能调用，通常不会生成 opsx-* prompt 文件。
  • Kimi Code：/skill:openspec-propose、/skill:openspec-apply-change
安装后命令不识别？先确认已运行 openspec init；升级后运行 openspec update，再重启对应 AI 工具。
