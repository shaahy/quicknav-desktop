AI Agent Design Rules

给 AI 一套
可执行的品味

Taste Skill 是一组面向 Codex、Claude Code、Cursor 等 AI 编程代理的前端设计指令。它不提供组件，而是规定代理如何理解需求、选择设计语言、组织布局、使用动效并完成交付检查。

本质可移植的 SKILL.md 规则集
核心目标减少模板味与 AI 设计痕迹
当前默认design-taste-frontend v2 experimental
Definition

它是什么

最准确的理解方式，是把它看成“给 AI 前端设计师使用的工作手册”。模型读到这些规则后，仍然负责生成代码，但它的判断空间被更具体的设计约束包围。

它把模糊的“做得高级一点”，翻译成 AI 可以逐条执行和检查的规则。

规则覆盖需求判断、设计系统映射、色彩与圆角一致性、Hero 纪律、区块去重复、动画实现、无障碍与交付前检查。仓库同时提供从零设计、旧项目改造、图片转代码和品牌视觉等专用 Skill。

×不是 UI 组件库
不会提供现成按钮、表格或卡片组件。
×不是前端框架
不替代 React、Vue、Svelte 或原生 Web。
×不是审美保证书
规则能抬高下限，但不能替代真实设计判断。
Why

它解决什么

AI 并非不会写 CSS，而是常在缺少约束时回到训练数据里最常见、最安全也最无聊的组合。Taste Skill 主要处理这种“默认化”。

未约束的 AI 输出

看起来完整，细看像同一个模板

  • 居中标题、胶囊标签、三张等宽功能卡
  • 每个区块重复同一种左右结构
  • 渐变、发光、装饰圆点被当成高级感
  • 凭空制造客户 Logo、状态数据和产品截图
  • 动画很多，却没有性能和减弱动效处理
Taste Skill 约束后

先建立设计逻辑，再选择表现形式

  • 先判断页面类型、受众、气质与参考体系
  • 统一强调色、圆角、字号和间距系统
  • 要求多个区块使用不同的布局家族
  • 禁止虚假内容和无意义的装饰性 UI
  • 高强度动画必须有真实实现和 reduced motion
Core Mechanism

运行机制

默认 v2 会先读取需求，再形成一句设计判断；随后映射合适的设计体系，通过三个调节参数控制结果，最后以硬规则和检查清单收口。

01

DESIGN_VARIANCE

布局实验程度。低值偏居中、克制和熟悉；高值允许更强的非对称与现代排版。

02

MOTION_INTENSITY

动效深度。低值只有基础反馈；高值可使用滚动联动、吸附和空间运动，但必须控制性能。

03

VISUAL_DENSITY

每屏信息量。低值适合品牌叙事；高值适合工具型界面和密集内容，但仍需清晰层级。

Brief → 一句话设计判断 → 设计系统映射 → 三参数调节 → 实现规则 → Anti-slop 禁令 → Pre-flight 检查
安装整个技能仓库
npx skills add https://github.com/Leonxlnx/taste-skill

CLI 会扫描仓库的 skills/ 目录。安装后仍应按任务选择 Skill，而不是在一次提示中同时调用全部规则。

只安装一个 Skill
npx skills add https://github.com/Leonxlnx/taste-skill --skill "design-taste-frontend"

也可以直接复制目标 SKILL.md 到项目或对话中。参数使用 frontmatter 的 name，不一定等于文件夹名。

Fit Check

适用场景

它最擅长视觉表达型前端。判断时不要只问“能不能做”，还要问这个 Skill 是否覆盖了该产品真正困难的部分。

从零制作视觉型页面 ✓

产品官网、Landing Page、发布页、活动页、作品集和品牌展示页。这是默认 Skill 的主战场。

改造已有项目外观 ✓

功能已完成，但信息层级、间距、布局和视觉一致性不理想。应使用 redesign Skill 先审计再修改。

图片先行的开发流程 ✓

先生成视觉参考图，人工选定方向，再让代理分析画面并实现代码，适合重视设计确认 Gate 的团队。

小团队快速建立下限 ✓

没有专职设计师，或需要产品经理、独立开发者快速完成可演示原型时，可用它建立共同规则。

复杂业务后台 !

大型数据表、密集仪表盘、多步骤表单和权限流程的难点在信息架构与业务逻辑，不是它的核心覆盖范围。

原生与实时协作产品 !

原生移动端、代码编辑器、多人实时协作界面需要平台级交互和状态设计，应搭配专门规范。

工作流

点击步骤查看每个阶段的输入、执行重点和输出。Taste Skill 不是一次性咒语，它更适合作为完整设计开发流程中的约束层。

Cheat Sheet

技能速查

仓库中的 Skill 各做一件事。实现型 Skill 输出代码，图片生成型 Skill 输出视觉参考图。不要为了“更强”一次叠加全部规则。

没有符合条件的 Skill，请清除搜索词或切换分类。

Recipes

实战配方

同一个仓库，三种任务对应三条不同路径。先决定交付物是代码、改造结果还是参考图，再选 Skill。

推荐 Skill

design-taste-frontend

适合需求基本明确、需要直接产出页面代码的任务。若使用 Codex 且希望约束更强，可换成 gpt-taste。

写清页面目的、受众、内容和技术限制。
让 Skill 推断设计语言，并确认三个参数。
生成代码并按 Pre-flight 清单自检。
人工确认视觉、真实内容和业务正确性。
使用 design-taste-frontend。为一款本地优先的知识工具制作中文官网。受众是独立开发者；视觉克制、编辑感强；不使用虚假客户 Logo。先声明设计判断与三个参数，再实现响应式页面。
推荐 Skill

redesign-existing-projects

适合保留现有功能和关键契约，在审计之后逐步改善视觉。不要直接把旧页面当作从零项目重写。

读取现有代码、截图、设计 Token 和不可变契约。
判断 Preserve、局部现代化或 Overhaul 模式。
列出布局、层级、间距和样式问题并排序。
按优先级修改，逐项回归原有功能。
使用 redesign-existing-projects。先审计当前界面，不要立即修改。必须保留 URL、导航名称、表单字段、品牌字样和功能行为。输出问题证据、改造优先级及验收标准，待确认后再实施。
推荐组合

imagegen + image-to-code

适合设计方向尚未确定，或者人工必须先批准视觉稿的工作。图片只是设计基线，不是最终可用产品。

用 imagegen-frontend-web/mobile 生成参考画面。
人工选择方向，确认内容与视觉默认值。
用 image-to-code 分析版式、字体、色彩和组件。
实现代码并进行响应式、交互和可访问性验证。
遵循 image-to-code 工作流：先生成参考图，再分析，最后编码。在视觉方向获得人工确认前不要实现页面。实现时以确认图为视觉基线，但使用真实文本和语义化 HTML。
Limits

边界与判断

Taste Skill 能降低“默认模板”出现的概率，但它仍是提示规则，不是确定性渲染引擎。最终质量取决于需求、素材、模型执行力和验证流程。

不能替代 UX 研究

它不知道真实用户最重要的任务、业务优先级和认知负担。信息架构与用户验证仍需单独完成。

不能制造真实内容

品牌文案、客户 Logo、数据、产品截图和社会证明必须来自真实来源，不能让 AI 为了画面完整而编造。

规则带有作者偏好

一些禁止项非常绝对。它们适合抑制常见 AI 痕迹，但不应凌驾于已确认的品牌规范和设计意图。

v2 仍是实验版本

默认 Skill 正在向 v2.0.0 stable 收敛。需要结果可重复的长期项目，应审查更新或显式固定 v1。

最合适的定位：设计起点、质量下限、反模板检查器。

它最有价值的地方，不是让 AI 突然拥有人的品味，而是把常见的设计判断转换成代理不容易跳过的硬规则。用它建立基线，用真实项目约束修正规则，再用人工 Gate 决定是否交付。
