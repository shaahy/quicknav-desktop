01

它到底是什么？

先把“模型”和“智能体运行框架”分开，很多困惑就消失了。

官方事实

DeepSeek Harness（命令名 dsh）是一个开源的 智能体运行框架。

它负责把模型、工具、会话记录、文件系统、权限审批、沙箱和界面组织到一起，让模型不只“回答问题”，还可以在受控条件下读取文件、修改代码和运行命令。

一句话类比：模型像“大脑”，Harness 像“工作台 + 手脚 + 安全规则”。

它不是什么

  • 不是 DeepSeek 大模型本身
  • 不是一个只会聊天的网页壳
  • 不是默认无条件执行的自动化机器人
  • 不是已经稳定定型的企业级成品
模型适配器连接 DeepSeek、OpenAI、Anthropic 或自定义兼容端点。
Agent Loop组织请求、工具调用、结果回填与下一步判断。
能力与安全文件、终端、工具、沙箱、权限审批都可替换。
会话与界面持久化事件日志，并通过 Web、Headless 或 SDK 使用。
02

什么时候值得用？

它更像可组合的智能体底座，而不是“下载即稳定办公”的大众应用。

教程判断

适合这些场景

  • 代码库理解：总结结构、定位模块、梳理依赖。
  • 受控开发：先规划，经确认后改代码、跑检查。
  • 智能体研发：更换模型、工具、沙箱或审批策略。
  • 自动化集成：通过 Headless 或 Python SDK 嵌入流程。
  • 插件实验：围绕明确扩展点增加新能力。
教程判断

暂时不太适合

  • 要求长期 API 稳定、零迁移成本的生产系统。
  • 只想要简单问答，不需要文件或工具能力。
  • 无法接受本地 Node.js、API Key 与权限配置。
  • 希望完全无人看管地修改高风险仓库。
  • 缺少隔离环境，却要让智能体接触敏感数据。
选择建议学习、试验和内部工具：值得体验；关键生产流程：先做小范围验证，并锁定版本与权限边界。

04

四种 Agent 模式怎么选？

它们不是“弱、中、强”四档模型，而是四套不同的 Agent preset：改变工具组合、调用方式和使用边界。

先记住一句话

日常开发选标准模式；多工具链式操作选 PTC 模式；刻意限制工具选极简模式；只有在创建 Agent preset 或实验插件时才选创造模式。

标准模式

standard

定位：功能完整的通用编码 Agent，也是 Web UI 的默认选择。

主要能力
  • 文件编辑、Shell、文件与网页检索
  • Skills、计划、目标、待办和上下文压缩
  • 子代理、工作流与后台任务
最适合
  • 理解代码库、修复缺陷、开发功能
  • “先分析 → 出计划 → 修改 → 验证”的完整任务
  • 不确定后续会用到哪些工具的日常工作
不必选它：任务只需两种基础工具，且你有意缩小能力面时，可以考虑极简模式。

PTC 模式

code

定位：保留标准模式全部能力，但通过 Code Mode SDK 把工具呈现给模型。

它怎样工作
  • 模型编写一个 TypeScript 程序组合工具操作
  • 由 run_code 执行程序，而非逐次发起每个工具调用
  • 适合“读取 → 筛选 → 处理 → 汇总”一类多步链路
最适合
  • 同一任务需要连续调用多个工具
  • 批量读取文件后按条件处理
  • 步骤明确、数据要在多个操作间传递的自动化
主要取舍：减少多步工具往返，不代表模型更强，也不保证所有任务都更快或更省 Token；简单修改通常没有明显收益。

极简模式

minimal

定位：固定提示词的双工具编码 Agent，只组合持久 Bash 与 str_replace_editor。

明确没有
  • 没有标准模式的计划、目标、Skills 与子代理工具
  • 没有网页工具、后台任务和工作流
  • 没有运行时上下文快照与上下文压缩
最适合
  • 简单、边界清楚的本地文件修改
  • 研究“双工具 Agent”怎样完成任务
  • 希望主动缩小工具面、观察基础行为
主要取舍：工具少不等于风险消失；Bash 仍可执行命令。复杂长任务也更容易受能力与上下文限制。

创造模式

cordis

定位：让 Agent 创建另一个 Agent；标准模式能力不变，再增加运行时自省与 preset 创作工具。

额外能力
  • 读取和修改当前 Harness 运行时
  • 临时挂载、测试和卸载插件
  • 提供 Cordis composition / preset 创作指导
最适合
  • 制作自定义 Agent preset
  • 验证工具、persona 与提示区段的组合
  • 理解 Host 与 Agent Preset 两个配置平面
高权限提醒：官方要求把它视为 Shell 访问。不要直接改内置 preset；复制成用户 preset 后再实验。

05

一次任务怎样流动？

理解这五步，就能知道“模型在想什么、工具何时执行、为什么会弹出审批”。

输入任务用户消息进入会话，系统准备当前工作区和上下文。
组装请求插件提供系统提示、工具定义和模型适配器。
模型判断模型回答，或决定调用文件、终端等工具。
受控执行工具经过策略与审批，执行结果写回会话。
继续或结束若还欠一步就继续；任务完成后关闭本轮。
官方架构要点

Step 是一次模型请求及其工具调用；Turn 可以包含零个或多个 Step。会话事件日志保存用户消息、模型消息和工具结果，恢复、分叉与回放都以此为基础。

06

完成第一个实战闭环

目标不是让智能体“一把梭”，而是练习最可靠的三段式：只读理解 → 计划确认 → 小步执行。

推荐新手：不用克隆仓库或手动构建，先体验 Web UI。需要联网下载 npm 包，并准备一个可用模型的 API Key。
1

准备一个安全的练习目录

不要第一次就把高价值仓库交给智能体。新建一个测试目录，并放入少量可修改文件。

mkdir dsh-demo
cd dsh-demo
已经安装兼容的 Node.js；源码仓库当前要求 ^22.19.0 || >=24.0.0。
练习目录不含真实密钥、客户数据或不可恢复文件。
2

启动 Web UI

npx @deepseek-ai/dsh web

终端会打印访问地址，默认通常是 http://127.0.0.1:3080。保持这个终端窗口运行。

3

配置模型

打开 设置 → 模型。使用 DeepSeek 时输入 API Key 并保存；也可以新增 OpenAI、Anthropic 或自定义 OpenAI 兼容端点。

配置保存后，下一个请求立即生效，不需要重启服务。
官方说明 API Key 按只写方式处理，页面保存后只收到脱敏描述。
4

选择工作区与标准模式

点击 选择工作区，添加并选择刚才的 dsh-demo；模式选择标准模式。未选择工作区之前，会话输入框不可用。

5

任务一：只读理解

先约束为只读，检查智能体是否正确理解目录。

发送这段提示词请只读检查当前工作区，不要修改文件或运行会改变状态的命令。告诉我：目录里有什么、每个文件可能做什么、有哪些风险或不确定项。

验收：回答基于实际文件；明确说明不确定项；没有产生文件变更。

6

任务二：先出计划

发送这段提示词为这个目录设计一个最小 README。先给计划，包含目标、文件范围、内容结构和验收标准。现在不要写文件，等我确认。

检查计划是否越界。满意后回复：“确认，按计划执行，只修改 README.md。”

7

验收结果

查看修改摘要：是否只出现 README.md。
打开文件检查：内容是否符合计划，是否凭空编造。
若弹出审批：先读清命令、路径和影响范围，再决定允许或拒绝。
发现偏差时，让智能体先说明原因，不要立刻扩大权限。
适合贡献者：需要 Git、兼容 Node.js、Corepack 管理的 pnpm。源码路线安装和构建时间更长，但便于读源码、开发插件与参与贡献。
1

克隆并进入仓库

git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness
2

安装与构建

corepack enable
pnpm install
pnpm run build

仓库当前固定 pnpm@11.7.0。首次开发环境搭好后，官方还建议运行 pnpm run typecheck。

3

启动源码版 Web UI

pnpm dsh web

随后按路线 A 的“配置模型 → 选择工作区 → 三段式任务”继续。

07

跑通以后，再看这些

先选一种入口解决真实问题，再决定是否深入架构和插件系统。

自动化

Headless 模式

运行一次任务、保存会话、打印最终答案后退出，适合脚本和 CI。

dsh --profile headless "job"
程序集成

Python SDK

从 Python 启动捆绑运行时并复用会话。官方入门要求 Python 3.10+，当前列出的目标平台为 Linux 与 macOS。

from deepseek_harness import DeepSeekHarness
深度定制

插件与 Profile

用 Bundle、Profile 与 patch 组合能力，不必直接修改“核心”。先输出实际配置树，再决定扩展点。

dsh --profile web --dump-config
FAQ

常见问题

先排除环境、工作区与模型配置，再怀疑 Agent Loop。

运行 npx 后没有打开网页？
命令只负责启动服务，不一定自动打开浏览器。查看终端打印的 URL，手动访问；默认通常为 http://127.0.0.1:3080。同时确认终端进程没有退出或报错。
为什么会话输入框不可用？
新的 Web UI 默认没有选中工作区。点击“选择工作区”，添加并选中项目目录后再开始会话。
保存 API Key 后模型仍不可用？
先确认提供方、模型和凭证匹配。AWS Bedrock、Vertex、Azure 与 Codex 等原生认证方式不只是填写普通 API Key；自定义提供方还需要正确的 Base URL、协议和模型 ID。
为什么工具执行前总要审批？
这是权限策略在工作。审批不是故障，而是风险控制点。应检查具体命令、目标路径和影响范围；对不理解或超范围的操作选择拒绝。
为什么切换模式后，当前会话没有变化？
模式属于会话创建时确定的 preset。当前会话开始产生输出后会被锁定；请选择目标模式后新建会话。
教程里的命令以后会不会失效？
可能。项目仍处于开发者预览，官方明确提示会有破坏兼容性的变更。遇到差异时，以当前仓库 README 和对应版本文档为准。
