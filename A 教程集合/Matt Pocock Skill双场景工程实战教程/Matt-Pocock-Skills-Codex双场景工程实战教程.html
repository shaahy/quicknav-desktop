认知路线阶段支线对话决策器检查表

From idea to reviewed change

在 Codex 里，
走对一条工程路线。

同一套 Matt Pocock Skills，在新项目 0→1和已有项目增量开发中，起点、判断依据和支线完全不同。这份教程用两个连续案例，教你何时调用、给什么输入、期待什么输出。

先记住这一条Skill 是条件路由，不是打卡清单。每个阶段只调用能消除当前不确定性的技能；如果产物已经存在，就直接把它交给下一阶段。

路线 A · 新项目 0→1

AI 客户访谈洞察平台：从模糊产品想法走到第一个通过审查的纵向切片。

路线 B · 已有项目增量

给已上线平台增加团队邀请与角色权限：先尊重现有事实，再完成小而完整的变更。

01 / MENTAL MODEL

使用前先把四件事分开

很多误用不是 Skill 不好，而是把路由器、编排器、底层纪律和产物当成一回事。

USER-INVOKED

用户调用型是流程入口

grill-with-docs、to-spec、implement 等需要你明确启动。它们负责组织一段流程。

MODEL-INVOKED

模型调用型是底层纪律

tdd、domain-modeling、codebase-design 可能被任务描述或其他 Skill 拉起。不要在编排器已经包含它们时重复启动。

ARTIFACTS

产物是阶段之间的接口

CONTEXT.md、ADR、Spec、Tickets、测试和 Review Report 承接上下文。下一阶段读产物，不重新发明需求。

HUMAN GATES

用户负责不可逆决策

范围、测试 seam、Ticket 粒度、Issue 状态、Commit 和冲突取舍需要人工确认。Skill 负责准备证据，不替你拥有决策。

Codex 调用写法：官方仓库用 /skill-name 表示用户调用。实际界面取决于安装方式；最稳妥的写法是同时明确点名技能和任务，例如：“使用 grill-with-docs，围绕以下想法逐项访谈……”

04 / BRANCHES

五个信号出现时，离开主线

支线用于解决主流程无法回答的问题。问题解决后带着产物返回，而不是把支线无限延长。

05 / CODEX DIALOGUE

在 Codex 中，一轮正确的协作长什么样

以下是教学对话，不是假装真实执行结果。注意用户何时提供输入、Codex 何时停下等待、产物如何传给下一阶段。

06 / DECISION HELPER

你现在应该调用哪个 Skill？

选择当前事实，不要选择你希望使用的技能。决策器只给建议，不运行任何操作。

07 / COMPARISON

两条路线最容易混淆的地方

增量开发不是缩短版 0→1。它多了既有约束、回归风险和变更基线。

比较点新项目 0→1已有项目增量
起点目标与未知，事实源尚未建立现有代码、CONTEXT、ADR、Issue 与用户行为
首要风险方向没想清就开始写代码澄清入口wayfinder 或 grill-with-docs领域模型第一次建立 canonical terms原型目的验证核心状态模型或产品交互Spec 重点V1 能力、范围、测试 seams审查基线Spec 与项目初始标准常见误用把所有未知都塞进第一版
08 / PRACTICE CHECKLIST

在自己的工程中照着检查

当每一项都有明确答案，你已经从“会调用 Skill”进入“会组织工程流程”。

我知道当前是新项目还是增量任务两者的输入、风险和起始 Skill 不同。
我只选了一个主流程入口没有同时启动多个访谈或规划编排器。
事实和决策有唯一落点CONTEXT 存词汇，ADR 存难逆权衡，Spec 存本次需求。
我知道哪些问题必须用原型回答只有纸面无法决定的状态或 UI 才进入 prototype。
测试 seam 已经得到确认测试观察公共行为，不跟内部实现绑定。
Tickets 是纵向且可单独验证的不是数据库、后端、前端各一张水平 Ticket。
实现阶段只有一个编排器implement 已含 tdd 和 code-review，不重复启动另一套流程。
审查有固定基线与 Spec 来源Standards 和 Spec 两轴分开，不互相掩盖。
上下文过长时先 handoff新会话引用既有产物，不在衰退上下文里硬撑。
任何外部写入都经过人工确认Issue、标签、Commit、Merge 与关闭请求都不是默认授权。

流程外独立工具

teach 用于多会话教学空间，writing-great-skills 用于 Skill 设计与评审。它们有价值，但不是本教程两条工程交付路线的一环；不要为了“用全 22 个”而硬插进项目流程。

事实来源

流程行为依据 mattpocock/skills 官方仓库及其公开 SKILL.md，核验日期 2026-07-20。页面中的案例、提示词和人工门槛是教学编排。

边界

本页不会安装或调用 Skill，不连接 Tracker，不创建代码库。实际执行前，请先检查技能版本、项目 AGENTS.md/CLAUDE.md 和写权限。
