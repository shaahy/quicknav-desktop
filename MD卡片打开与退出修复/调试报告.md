# MD 卡片打开与退出修复

状态：已修复并完成回归验证

## 基线现象

- 点击本地卡片“工作记录”时，Main 进程在写调试日志阶段抛出
  `EPIPE: broken pipe, write`。
- 文件打开动作没有执行，Renderer 随后显示打开失败或加载失败反馈。
- 错误界面的“退出”同样在 Main 进程写日志时被 `EPIPE` 中断，
  `app.quit()` 没有执行。

## 根因与验证

### 根因

1. Main 进程在执行打开文件和退出操作前写入 `console.log`。开发进程的
   stdout 管道关闭后，日志写入触发未处理的 `EPIPE`，因此真正的文件打开
   和 `app.quit()` 都没有机会执行。
2. Windows 文件打开使用 `cmd /c start`，调用是异步且返回值不能可靠表示
   系统是否真正打开文件。
3. 错误界面的“退出”按钮绕过 React 事件系统绑定原生 `onmousedown`，
   退出链路缺少稳定的组件级回归覆盖。
4. `shell.openPath()` 从开发版 Electron Main 进程启动默认应用时，MarkText
   继承了 `ELECTRON_RENDERER_URL=http://localhost:5173` 和
   `NODE_ENV=development`。由于 MarkText 本身也是 Electron 应用，它先错误
   加载了速查工具的 Vite 页面；仅清除开发 URL 后又按开发模式构造出空 URL，
   抛出 `TypeError: Invalid URL`。这是人工测试中 MD 仍打不开的最终根因。

### 修复

- 在 Main 进程初始化最前面为 stdout/stderr 安装 `EPIPE` 防护；其他流错误
  仍会抛出，不被静默吞掉。
- 使用 Electron `shell.openPath()` 打开本地文件，并根据其返回的错误字符串
  区分“没有默认应用”和未知错误。
- 默认应用启动期间串行隔离开发环境：移除 Electron/Vite Renderer URL，并将
  `NODE_ENV` 临时设为 `production`；打开调用结束后完整恢复速查工具的原环境，
  避免 Electron 默认应用误入开发模式。
- 移除打开文件、退出链路上会阻断关键动作的调试日志。
- 错误界面的“退出”改为标准 React `onClick`，退出统一走
  `renderer -> preload -> IPC -> app.quit()`。

- 环境隔离回归测试先后复现了 Renderer URL 泄漏和 `NODE_ENV=development`
