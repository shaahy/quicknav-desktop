## 3. 发现的缺口

### G-01｜体验意图仅被间接表达

上游提出“无需离开当前思路，就能立即恢复所需框架知识”，并明确“方便为最高优先级”。PRD 已通过产品愿景、5 秒/2 次核心操作、常驻类别导航和全局搜索承接效率目标，但没有直接保留“不打断当前思路/快速恢复知识上下文”这一体验语气。

- 类型：定性体验保真缺口
- 严重度：低，非 Finalize 阻塞项
- 影响：不会改变 FR 或验收口径，但 UX 阶段若只读结构化需求，可能弱化“保持工作流连续性”的设计原则。
- 建议处理：在后续 PRD 修订或 UX handoff 中补一条体验原则；若认为 5 秒/2 次操作已足够表达，可明确接受当前间接承接方式。

### G-02｜技术选型的用户顾虑与权衡未完整进入 addendum

上游记录了用户对 Tauri 开发复杂度的顾虑、对 Windows 可执行程序与 macOS 应用交付结果的关注，以及 Electron + 原生 HTML/CSS/JavaScript 可能以安装体积换取开发简单度的讨论。现有 addendum 只保留了“Tauri、Electron 或其他方案未决定”和“构建、签名、安装包未决定”，没有保留这组取舍理由。

- 类型：Architecture 输入深度缺口
- 严重度：低，非 PRD 产品范围阻塞项
- 影响：Architecture 仍知道候选方案和必须满足的跨平台交付结果，但缺少评估候选方案时应重点比较的“开发复杂度/技术熟悉度/安装体积/最终安装形态”。
- 建议处理：在 Architecture 启动前把这组评估维度补入 addendum；不得据此提前选定 Electron 或 Tauri。

## 5. 专项检查

### 5.1 当前有效产品内容是否遗漏

没有阻塞性遗漏。主动选择、禁止扫描、卡片唯一对象、用户类别、多类别归属、首页切换、个人本地使用、Windows/macOS、低成本定位与打开等核心内容均有对应要求。唯一值得保留的软性信息为 G-01。

### 5.2 技术实现、拒绝方案与下游事项是否正确安置

总体正确。框架、存储、打包、路径唯一性、启动检查机制和数据升级均位于 addendum；自动扫描等被拒绝方案留在历史输入中，未进入现行产品范围。G-02 仅涉及选型理由深度，不影响边界正确性。

### 5.3 旧内容是否错误复活

- **HTML 专属定位：未复活。** 现行对象是任意文件；HTML 页面标题只作为 HTML 文件默认命名的合法特例，由后续明确 override 保留，不代表产品重新限定为 HTML。
- **默认浏览器打开：未复活。** FR-017 已改为操作系统默认方式处理，FR-018 覆盖无默认关联应用的异常流程。
- **冻结 Tauri/Electron：未复活。** PRD 明确不冻结，实现选择只在 addendum 中作为候选议题。
- **跨设备路径映射：未复活。** FR-027 明确两端数据独立；addendum 只把路径映射记录为已讨论但不形成 V1 需求。

### 5.4 FR 结构是否丢失语气或体验意图

主要体验结构没有丢失：用户主动控制收录、常驻导航、快速切换、名称搜索、2 次核心操作、明确失败反馈与不改原文件均已制度化。仅 G-01 所述的“不中断当前思路、恢复知识上下文”没有直接成为体验原则。
