# 本地文件导航工具 · Experience Spine

`EXPERIENCE.md` 定义信息架构、行为、状态、交互、无障碍与旅程；同级 `DESIGN.md` 是视觉身份引用。后续 Mock、线框或导入稿与两份 Spine 冲突时，以 Spine 为准。正式 Mock 为 [首页与整理排序](mockups/key-home.html)、[新增卡片](mockups/key-add-card.html)、[编辑卡片](mockups/key-edit-card.html) 和 [失败修复与重复冲突](mockups/key-repair-failure.html)；`.working/` 只保留 Discovery 与视觉检查证据。

## Foundation

- **形态：** Windows 与 macOS 的单窗口桌面应用；两端产品界面、能力、业务规则和验收结果一致。
- **产品边界：** 用户主动选择单个源文件，应用只维护导航卡片并向操作系统发起打开或定位请求；不扫描、不预览、不编辑、不移动、不删除源文件。
- **平台边界：** 系统文件选择器、选择打开方式、资源管理器 / Finder、安全提示和窗口控制遵循平台原生规范。
- **数据边界：** 两台设备完全独立；界面不得暗示同步、迁移、导入、导出或共享。
- **实现边界：** 不指定 UI 实现库，也不冻结 Electron、Tauri、JSON、数据库、文件唯一性算法、构建、签名、安装或升级方案。
- **视觉：** 浅色“结构化索引 + 档案绿标”，引用 `DESIGN.md`。应用壳使用 `{colors.canvas}`、`{colors.surface}` 与 `{colors.border}`；键盘焦点使用 `{colors.focus}`。

## Information Architecture

### 产品内 Surface

| ID | Surface | Reached from | Purpose |
|---|---|---|---|
| S01 | 全部卡片正常态 | 每次启动；左侧栏固定顶部 | 唯一汇总全部卡片；响应式网格；同一卡片只出现一次 |
| S02 | 用户类别正常态 | `category-item` | 展示当前用户类别及其独立顺序 |
| S03 | 未分类正常态 | “未分类”自身至少有一张卡片时在左侧栏固定底部 | 恢复失去全部用户类别的卡片；不可主动加入 |
| S04 | 全局搜索结果 | `global-search` 非空有效输入 | 跨全部卡片实时显示名称匹配；保持左侧当前类别 |
| S05 | 首次无卡片空状态 | 空数据启动进入 S01 | 说明不会扫描磁盘；主行动“选择文件” |
| S06 | 用户类别空状态 | 空的用户类别 | 主行动“选择文件”；次要入口“查看全部卡片” |
| S07 | 搜索无结果状态 | 搜索无匹配 | 显示查询词并提供清空搜索 |
| S08 | 卡片整理排序模式 | 当前视图“整理排序” | 禁止卡片主打开；调整当前视图独立顺序 |
| S09 | 类别整理排序模式 | 类别栏“整理类别” | 仅调整用户类别；系统视图固定 |
| S10 | 新增卡片确认模态框 | 系统文件选择器成功返回 | 确认名称、类别；必要时创建第一个类别；明确保存 |
| S11 | 卡片编辑模态框 | `action-menu`“编辑”或查看原卡片 | 编辑名称、备注、类别和文件关联；查看只读完整路径 |
| S12 | 新建或重命名类别浮层 | 左侧“＋”、类别 `action-menu` 或 S10 内新建 | 单字段编辑与就地校验 |
| S13 | 删除类别确认 | 类别 `action-menu`“删除” | 显示类别名、卡片总数、进入未分类数量与安全边界 |
| S14 | 删除卡片确认 | 卡片 `action-menu` 或失败对话框 | 确认从所有类别移除；明确源文件不变 |
| S15 | 放弃未保存修改确认 | 有实际修改时关闭 S10 / S11 | 继续编辑或放弃修改 |
| S16 | 无法打开文件对话框 | 操作系统未处理主打开请求 | 保留卡片；重新选择、删除或关闭 |
| S17 | 无法定位文件对话框 | 资源管理器 / Finder 无法定位 | 保留卡片；重新选择、删除或关闭 |
| S18 | 重复源文件冲突对话框 | 新增、主动更换或修复时命中已有卡片 | 查看原卡片、重新选择或取消；不覆盖关联 |

左侧 `category-nav` 固定：全部卡片在顶部，用户类别位于中段；仅当“未分类”自身至少有一张卡片时显示该系统类别，并固定在底部。切换类别只替换主展示区，不创建页面层级。右侧由 `view-header`、常驻 `global-search`、工具区和卡片网格组成。

Mock 覆盖映射：[S01 / S08 首页与整理排序](mockups/key-home.html)；[S10 新增确认](mockups/key-add-card.html)；[S11 编辑卡片](mockups/key-edit-card.html)；[S16 / S18 失败修复与重复冲突](mockups/key-repair-failure.html)。未单独渲染的 Surface 继续由本 Spine 的状态、组件和旅程契约承载。

### 外部系统交互

| ID | System surface | Contract |
|---|---|---|
| X01 | 系统文件选择器 | 一次选择一个文件；用于新增、主动更换和重新关联。取消不创建或改变记录，并按来源返回原 Surface 与原“选择文件 / 重新选择文件”触发控件。 |
| X02 | 系统选择打开方式 | 无默认关联应用时由系统承载；取消不改变任何应用或文件状态，回原 `file-card` 主体。 |
| X03 | Windows 资源管理器 / macOS Finder | 定位源文件；系统界面结束且产品重新获得前台焦点时，回发起定位的原控件；失败进入 S17。 |
| X04 | 操作系统安全提示 | 产品不得绕过或屏蔽；语言跟随系统；提示结束且产品重新获得前台焦点时，回发起打开的原 `file-card` 主体。 |

## Voice and Tone

微文案冷静、直接、工具化；品牌人格见 `DESIGN.md` 的 Brand & Style。

| Situation | Use | Avoid |
|---|---|---|
| 首次空状态 | “添加常用文件。应用不会扫描磁盘。” | “让我们开始打造你的资料库！” |
| 打开失败 | “无法打开文件。卡片仍被保留。” | “糟糕，文件好像消失了。” |
| 定位失败 | “无法定位文件。卡片仍被保留。” | “路径错误。” |
| 删除卡片 | “将从所有类别移除，但不会删除、移动或修改源文件。” | “确定删除吗？” |
| 删除类别 | 显示类别名、卡片总数、进入未分类数 | 模糊使用“相关内容可能受影响” |
| 成功反馈 | “已重新关联。” / “已移出当前类别。” | “太棒了！操作成功！” |
| 校验 | “名称最多 80 个字符。” / “请至少选择一个类别。” | 错误码或未说明修复方式的“无效输入” |

## Component Patterns

行为组件与 `DESIGN.md.Components` 使用完全相同的规范键名。

| Component | Use | Behavioral contract |
|---|---|---|
| `app-shell` | S01–S09 的单窗口容器 | 每次启动进入 S01；本地数据未就绪时先显示稳定应用壳和“正在加载本地数据”，导航、搜索、工具与卡片区不暴露可误操作焦点。加载失败仍留在 S01，以和标题、说明关联的阻断反馈提供“重试 / 关闭应用”，初始焦点落“重试”；状态从加载中变为失败时只宣告一次，不显示技术错误或推断恢复机制。类别切换不入新页面；对话框结束后恢复原主区上下文。类别导航、主内容、搜索和当前视图标题必须能被辅助技术识别。 |
| `category-nav` | 常驻左侧栏 | 标题区提供“＋”与“整理类别”可见入口；固定显示全部卡片；用户类别依用户顺序；仅当未分类自身至少有一张卡片时显示该系统类别。导航区具备可识别名称，当前类别同时以程序化当前态表达。不得折叠或转顶部导航。 |
| `category-item` | 系统视图与用户类别 | 名称区域只切换视图；用户类别常驻独立更多按钮。全部卡片和未分类无编辑/删除菜单。 |
| `view-header` | 主区顶部 | 显示当前视图名称及必要数量/排序信息；当前视图标题程序化命名主内容与卡片集合。类别切换或搜索清空后，标题变化成为可感知上下文但不强制移动键盘焦点。承载常驻搜索与可见工具入口。 |
| `global-search` | S01–S09 常驻 | 非空输入实时按展示名称搜索；忽略首尾空格，英文不区分大小写。搜索区具备可识别名称，并由当前视图标题提供上下文。清空或 `Esc` 回到原类别。排序：完整名称、名称开头、其他包含；同层级沿用全部卡片顺序。 |
| `toolbar-button` | 选择文件、整理排序、整理类别及对话框行动 | 所有功能有可见入口；V1 无全局组合快捷键。主次层级稳定，禁用项须解释原因。 |
| `file-card` | S01–S04、S08 | 主体单击/Enter 直接请求系统按默认方式处理，不预检查文件状态。卡片集合由当前视图标题命名；每张卡片向辅助技术暴露名称及在当前集合中的位置/总数。主体与常驻更多按钮是分离点击和焦点目标；备注最多两行，无备注不留空位。 |
| `file-type-mark` | `file-card` 顶部元信息 | 只根据文件名/扩展名显示图标+扩展名；不读取、预览或推断内容，不改变打开方式。 |
| `category-tag` | S01 与 S04 | 最多显示两个类别，更多用“+N”；仅识别，不可点击。S02/S03 隐藏。 |
| `action-menu` | 卡片与用户类别更多按钮 | 卡片菜单：编辑、在文件管理器中显示、删除；“移出当前类别”只在 S02 显示，若仅属当前类别则以不可激活的禁用菜单项保留并解释。类别菜单：重命名、删除。菜单具备菜单、菜单项、禁用项的等价程序化语义；菜单操作不得触发卡片打开。 |
| `card-form-dialog` | S10 与 S11 | 新增与编辑共用容器和操作骨架，均以名称字段作为初始焦点。S10 提供名称与类别；HTML 优先采用去除首尾空格后的有效 `<title>`，标题不可读、缺失、为空或仅含空白时回退到不含扩展名的文件名，非 HTML 直接使用不含扩展名的文件名。S11 提供名称、完整备注、类别、只读完整路径、复制路径、在文件管理器中显示和重新选择文件。新增仅明确保存才创建；关闭时只在实际修改后转 S15。 |
| `category-editor-popover` | S12 | 锚定触发位置、窗口边缘避让；打开后焦点进入名称；`Esc`/取消关闭并把焦点还给触发者；创建成功后在 S10 中自动选中新类别。 |
| `category-checklist` | S10/S11 | 展开式复选组，具有可访问组名、选择说明，以及与整个组程序化关联的“至少选择一个类别”错误；选择状态始终可见。组级校验失败时聚焦组内第一个类别；若尚无用户类别，聚焦组内“新建类别”，并播报组错误。新增时始终不预选，不因发起视图推断类别。未分类不可选。 |
| `confirmation-dialog` | S13/S14/S15 | 居中且一次只处理一个决定。具备与标题、关键后果关联的对话框语义；破坏性确认初始焦点落在安全动作。删除从失败流程进入时替换错误框，不堆叠。取消/关闭保持原状态。S15 仅“继续编辑 / 放弃修改”。 |
| `error-dialog` | S16/S17 | 标题区分打开与定位失败；具备与标题、说明关联的对话框语义，初始焦点落在非破坏性的修复动作。明确卡片保留；提供重新选择、删除卡片、关闭。删除必须转 S14，不直接执行。 |
| `duplicate-dialog` | S18 | 显示“该文件已收录”和原卡片名；具备与标题、冲突说明关联的对话框语义，初始焦点落在“查看原卡片”。提供查看原卡片、重新选择、取消。不创建第二张卡片，不覆盖当前关联。离开有修改表单前遵循 S15。 |
| `reorder-control` | S08/S09 | 显式整理模式中显示拖动手柄及键盘“上移 / 下移”。移动结果立即生效，无需额外保存；正常关闭、重新打开、系统重启和正常升级后顺序保持。保持焦点并播报名称、当前位置和总数；写入时机与恢复机制属于 Architecture。 |
| `empty-state` | S05/S06/S07 | S05 只突出“选择文件”；S06 为“选择文件”主行动与“查看全部卡片”次行动；S07 显示查询词并允许清空。不得展示虚构示例卡片。 |
| `status-bar` | 非阻断成功 | 锚定主区域底部，至少保持 8 秒、可关闭、礼貌级读屏播报且不抢焦点；不遮挡操作、不推动布局。键盘焦点位于状态条内或指针悬停时暂停自动消失；手动关闭或最终移除时，若焦点位于其中，则回到触发该状态的稳定控件或对应卡片且不重复播报。自动消失后结果仍能从当前卡片或视图状态核对。重新关联后提示但不自动重试原系统动作。 |
| `form-field` | S10–S12 | 名称去首尾空格后校验；卡片名单行≤80且不完全重名，冲突时阻止保存并提示或定位同名卡片；类别名单行≤30，不能使用“全部卡片”“未分类”且不得完全重名；两类名称均允许大小写不同并存。S11 的备注为纯文字≤500，换行计入字符数，纯空白视为未填写，可新增、编辑或清空；不支持富文本、Markdown、图片、链接预览或附件。S11 的路径只读、可复制、可请求 X03 定位，变更只经 X01。字段错误与对应字段建立程序化关联；提交失败时聚焦首个无效字段并播报错误。 |

## State Patterns

### Surface 状态覆盖

| Surface | Required states | Treatment |
|---|---|---|
| S01 全部卡片正常态 | 本地数据加载中、加载失败、启动完成、有卡片、焦点、网格自适应 | 先显示稳定应用壳；加载中播报“正在加载本地数据”，操作控件不可聚焦或激活。成功后进入全部卡片并按左栏、标题/搜索/工具、网格建立焦点顺序；失败时显示非技术化阻断反馈，初始焦点落“重试”，另有“关闭应用”。不规定加载、存储或损坏恢复机制。 |
| S02 用户类别正常态 | 有卡片、焦点、卡片移出后 | 保留独立顺序；编辑后移出当前类别，卡片消失并显示 `status-bar`。 |
| S03 未分类正常态 | 有卡片、卡片重新归类后、焦点 | 仅恢复来源；加入任一用户类别后自动离开；不可主动添加。 |
| S04 全局搜索结果 | 输入中、有结果、焦点 | 视觉结果随输入实时更新；读屏状态采用可取消、可合并的礼貌级播报，在短暂输入停顿后只播报最新查询的结果数。无结果、清空与返回原类别分别播报一次，不把每张卡片内容加入 live region；同一卡片一次；左侧当前类别不变。 |
| S05 首次无卡片空状态 | 空数据、焦点 | 使用 `empty-state`；选择器取消后原样保留。 |
| S06 用户类别空状态 | 空类别、焦点 | 主/次入口明确；不引入批量归类。 |
| S07 搜索无结果状态 | 无匹配、清空 | 显示查询词；清空或 `Esc` 返回原类别。 |
| S08 卡片整理排序模式 | 进入、拖动、键盘移动、退出 | 卡片主体停止打开；只改当前视图；移动结果立即生效、无需额外保存，并播报位置；顺序的可感知持久化遵循跨 Surface 规则。 |
| S09 类别整理排序模式 | 进入、拖动、键盘移动、退出 | 仅用户类别可移动；全部卡片与未分类固定。 |
| S10 新增卡片确认模态框 | 初始、修改、校验错、类别为空、保存、取消 | 类别始终不预选；无类别可开 S12 创建并自动选中；明确保存前无记录。 |
| S11 卡片编辑模态框 | 初始、修改、校验错、保存、取消、重新选择中 | 保存保留未变数据和各视图顺序；主动更换命中重复转 S18且原路径不变。 |
| S12 新建或重命名类别浮层 | 初始、校验错、保存、取消、边缘避让 | 错误就地显示；关闭还焦；不为系统视图提供此态。 |
| S13 删除类别确认 | 有卡片、空类别、确认、取消 | 始终显示总数与进入未分类数；确认后若删除当前类别，切到 S01。 |
| S14 删除卡片确认 | 确认、取消 | 确认移除卡片全部关系和顺序；源文件不变；取消全部不变。 |
| S15 放弃未保存修改确认 | 继续、放弃 | 无修改不出现；继续返回表单且数据完整；放弃回原上下文。 |
| S16 无法打开文件对话框 | 失败、关闭、重新选择、删除 | 失败前不检查；关闭后可再次点卡片；卡片数据保持。 |
| S17 无法定位文件对话框 | 失败、关闭、重新选择、删除 | 不预检查；关闭/失败不改变数据；删除转 S14。 |
| S18 重复源文件冲突对话框 | 新增冲突、更换冲突、修复冲突、查看原卡片、改选、取消 | 新增不创建第二张；更换/修复保留原关联；查看原卡片进入 S11。 |

### 跨 Surface 规则

- **新增成功落点：** 当前视图能展示新卡片则保持；否则切到 S01，使新卡片立即可见。
- **新增顺序：** 新卡片追加到“全部卡片”及每个所属用户类别的末尾；任何卡片因删除类别而进入“未分类”时，追加到“未分类”末尾。
- **类别删除：** 仍有其他用户类别的卡片保持；失去全部用户类别的卡片进入 S03 末尾。删除当前类别后切到 S01。
- **重新关联成功：** 保留名称、备注、类别关系及所有视图顺序；回原主区，`status-bar` 提示“已重新关联”；不自动打开或定位。
- **外部系统返回落点：** 采用“来源保持”。从 S01/S02/S03/S05/S06 发起 X01，取消后回同一 Surface 的原“选择文件”；从 S11 发起则回 S11 的“重新选择文件”，保留未保存修改与原关联；从 S16/S17 发起则分别回 S16/S17 的“重新选择文件”，原关联及卡片数据不变；从 S18 发起则回 S18 的“重新选择”，冲突上下文与原关联不变。X02 取消回原 `file-card` 主体。X03 正常返回时，主区发起回原卡片“更多”按钮，S11 发起回其“在文件管理器中显示”；X03 失败进入 S17，初始焦点落在非破坏性的“重新选择文件”。X04 结束后回原 `file-card` 主体。若原触发控件因数据变化已不存在，回同一 Surface 的首个安全主操作；不得跳转到其他类别或丢弃表单状态。
- **X01 成功返回：** 新增文件选择成功进入 S10，初始焦点落名称字段；S11 主动更换成功返回 S11，更新只读路径并聚焦“重新选择文件”，其他未保存修改保持；S16 修复成功关闭失败流程，回原主区的原 `file-card` 主体；S17 修复成功关闭失败流程，回原卡片“更多”按钮；两者均显示不抢焦点的“已重新关联”状态条且不自动重试。若从 S18“重新选择”继续，按冲突出现前的原始工作流执行上述唯一落点：新增回 S10 名称字段，主动更换回 S11“重新选择文件”，打开修复回原卡片主体，定位修复回原卡片“更多”按钮。X01 未能完成选择时等同取消：数据保持，回来源的“选择文件 / 重新选择文件”，并以一次非技术化状态说明未完成。
- **系统不可用不是预检查状态：** 外接盘、网络位置或云盘目录不可访问，只在实际打开/定位请求失败后进入 S16/S17；不显示“检查中”、不可用徽标或自动恢复状态。
- **持久化可感知结果：** 正常关闭、重新打开、系统重启与正常升级后，卡片及其应用内数据和手动顺序应恢复可用；V1 不保证卸载后保留数据，也不要求重新安装后自动恢复。加载中与失败时的可见状态遵循 S01；具体写入时机、加载、损坏恢复与存储机制属于 Architecture。

## Interaction Primitives

- **指针：** 单击 `file-card` 主体执行主打开；单击独立更多按钮打开 `action-menu`。拖动仅在 S08/S09 显式整理模式可用。
- **键盘：** 全部功能使用 Tab、Shift+Tab、方向键、Enter、Space、Esc 完成；不设置全局组合快捷键。Enter/Space 激活聚焦控件，Esc 关闭顶层菜单/浮层/对话框、退出整理或清空搜索，按当前上下文只执行一层。
- **焦点：** 打开菜单、浮层、模态时焦点进入容器；容器具备程序化标题和必要描述，关闭后回触发者。模态内焦点循环；破坏性确认先聚焦安全动作；保存后移动到结果可感知位置，删除后移动到稳定相邻项或主区标题；校验失败聚焦首个无效字段。
- **排序：** 指针拖动与键盘按钮结果等价。S08 只影响当前视图；S09 只影响用户类别。移动后焦点留在被移动项。
- **系统请求：** 主打开与定位都不先判断文件状态；请求成功交给系统即完成产品动作，请求失败进入对应对话框。
- **动效：** 仅焦点、悬停、浮层出现和排序位置变化使用短过渡；系统“减少动态效果”开启时取消非必要过渡，状态立即更新。
- **禁止：** 双击打开、长按排序、悬停才出现管理入口、自动扫描、自动重试系统动作、卡片/类别批量操作、隐藏式右键唯一入口、模态堆叠超过一层。

## Inspiration & Anti-patterns

- **保留的启发：** “结构化索引”用硬边界、方形组件、稳定位置和紧凑网格建立可审计秩序；“档案绿标”只标记行动与当前项；系统中文无衬线负责阅读，等宽字体只辅助数量、顺序与路径核对。
- **拒绝双击打开：** 主操作必须单击与键盘直接可达，避免桌面习惯猜测与无障碍分歧。
- **拒绝顶部或下拉类别导航：** 固定左栏让类别与当前上下文持续可见，不因窗口变化引入第二套 IA。
- **拒绝独立详情页：** 新增与编辑留在居中模态，保持首页与卡片上下文。
- **拒绝自动扫描、预检查与自动重试：** 用户明确选择文件；系统动作只在真实请求时反馈，重新关联后由用户再次触发。
- **拒绝密度切换、深色主题和装饰动效：** V1 保持单一浅色、均衡紧凑密度与功能化短动效，避免新增偏好状态和非核心验收面。

## Accessibility Floor

- 适用 WCAG 2.2 AA 的完整桌面基线；视觉对比引用 `DESIGN.md` 的语义色组合。
- 每项功能均有键盘路径；Tab 顺序与视觉阅读顺序一致。类别列表、复选列表和菜单使用符合控件语义的方向键导航。
- 焦点始终以 `{colors.focus}` 可见外环呈现，不与 `{colors.action}` 当前态混淆；错误、成功、警告、选中和禁用均不只依赖颜色。
- `file-card` 主体与更多按钮具有独立可访问名称。例如“打开：产品需求文档”和“更多操作：产品需求文档”。
- 搜索结果更新、排序位置变化与 `status-bar` 采用礼貌级播报；实时搜索只合并播报最新结果数；阻断错误与确认对话框在打开时宣告标题和关键后果。
- 字体与界面兼容系统缩放/文字放大；在受支持系统的 200% 文本或显示缩放等价条件下，UJ-1 至 UJ-4 无文字裁切、控件遮挡或功能丢失。控件可增高；模态和浮层内容可滚动且操作区可达。侧栏类别名视觉截断时，其完整名称仍由可访问名称提供。备注可截断为两行，但完整内容在 S11 可读。
- 在系统或辅助技术支持文字间距调整时，以行高 1.5 倍、段后距 2 倍字号、字距 0.12 倍字号、词距 0.16 倍字号的等价条件验收，无文字裁切、遮挡或内容/功能丢失。V1 是具有约 760×560 最小窗口和固定导航/主内容二维布局的原生桌面产品，不把 320 CSS px 浏览器视口作为支持场景；在最小支持窗口与 200% 等价缩放下，主区降为一列并纵向滚动，不产生主内容横向滚动。
- 拖动不是排序唯一方式；`reorder-control` 的上移/下移按钮具备项目名、方向和可用状态。
- 减少动态时取消非必要过渡；功能反馈、焦点和位置结果完整保留。
- 平台原生 X01–X04 的无障碍由系统承担；产品必须提供清楚的发起控件，并按“外部系统返回落点”契约恢复 Surface、数据上下文与键盘焦点。

## Responsive & Platform

| Context | Contract |
|---|---|
| 常规 1024×720 | 固定左侧栏；主区约三列均衡紧凑卡片；搜索与工具保持可见。 |
| 最小约 760×560 | 左侧栏仍固定；主区逐步降至一列；必要时主区滚动，不折叠侧栏、不变列表。 |
| 大于常规窗口 | 不设 UX 最大宽度；按可用宽度增加卡片列数，卡片保持可读最小宽度。 |

| macOS | 产品界面与业务规则一致；X01/X02/X03/X04 使用 macOS 原生行为与窗口控制。 |

## Product Boundaries & Validation Invariants

| Invariant | UX evidence |
|---|---|
| 5 秒、2 次核心操作 | “切换类别 + 点击卡片”或“输入完整搜索词 + 点击结果”；移动、滚动与等待不计。 |
| 一源文件一卡片 | S18 阻止新增/更换/修复冲突，并提供原卡片入口；等价判定算法交给 Architecture。 |
| 源文件安全 | 所有删除确认与失败文案说明只影响应用内卡片/关系；不删除、移动、重命名或修改源文件。 |
| 视图顺序独立 | S08 只改变当前视图；同一卡片在其他视图的位置不变。 |
| 失败不静默 | 主打开失败到 S16，定位失败到 S17；卡片保持并有明确后续动作。 |
| 双设备独立 | 无同步、迁移、导入、导出或共享入口及暗示。 |
| 系统安全边界 | 可执行文件与脚本不加产品警告，但 X04 不得被绕过或屏蔽。 |

## Key Flows

### UJ-1：首次建立导航库（怡哥，第一次打开空应用，准备收录常用 PRD）

1. 怡哥启动应用，`app-shell` 进入 S05；左侧只有固定“全部卡片”，主区说明应用不会扫描磁盘。
2. 他激活“选择文件”，进入 X01；一次选择一个本地文件。
3. X01 返回后进入 S10：HTML 优先使用去除首尾空格后的有效 `<title>`，否则使用不含扩展名的文件名；非 HTML 使用不含扩展名的文件名。类别列表为空且不预选。
4. 他在 `category-checklist` 中打开 S12，输入第一个类别名并保存；新类别自动选中。
5. 他确认名称，激活“保存”。
6. **Climax：** 卡片创建后立即在可展示它的 S01/S02 出现；名称、类型、备注摘要规则和类别归属可直接核对。

Failure paths:

- 在 X01 取消 → 返回 S05，不创建记录。
- 名称为空、换行、超长或重名，或未选类别 → S10 就地解释并阻止保存。
- 源文件已收录 → S18 显示原卡片名；查看原卡片、重新选择或取消，不创建第二张。
- S10 有修改后关闭 → S15；放弃不留下卡片或临时记录。

### UJ-2：日常快速打开（怡哥，工作中需要立即打开已收录预算表）

1. 怡哥启动应用，稳定落在 S01，不恢复上次类别。
2. 若目标可见，他直接聚焦/点击 `file-card`；若不可见，他只执行一种查找动作：切换类别，或在 `global-search` 输入完整搜索词。
3. 搜索路径中，结果按完整名称、名称开头、其他包含实时排序；类别路径中，网格沿用该视图独立顺序。
4. 他点击目标卡片主体；应用不预判文件状态，直接请求操作系统默认处理。
5. 有默认应用则由系统打开；没有默认应用则进入 X02。
6. **Climax：** 在“切换/输入 + 点击”不超过两次核心操作、目标有效的前提下，文件在 5 秒内成功交给操作系统。

Failure paths:

- X02 取消 → 卡片、类别、顺序和文件均不变，回原主区。
- 系统未处理打开请求 → S16 明确“无法打开文件，卡片仍被保留”；可重新选择、删除或关闭后再次点击重试。
- 搜索无匹配 → S07 显示查询词；清空或 Esc 返回原类别。

### UJ-3：整理同一张卡片（怡哥，整理项目资料与常用模板中的同一文件）

1. 怡哥从 S02 的卡片 `action-menu` 打开 S11。
2. 他在 `category-checklist` 中保留当前类别并勾选另一个用户类别，然后保存。
3. 他分别进入两个类别；同一张卡片都可见，且各自位置独立。
4. 在第一个类别进入 S08，用拖动手柄或上移/下移调整卡片；移动结果立即生效，无需额外保存。
5. 切换到第二个类别，原有位置未受影响；他可在该视图单独调整。
6. 回到第一个类别，从 `action-menu` 执行“移出当前类别”；若卡片仍属另一类别则允许。
7. **Climax：** 卡片从当前网格消失并显示“已移出当前类别”，而另一类别中的同一卡片与其顺序保持不变。

Failure paths:

- 卡片只属于当前类别 → “移出当前类别”禁用并解释“请先加入其他类别”。
- S11 取消勾选当前类别但仍有其他类别并保存 → 留在当前视图，卡片消失并提示；其他类别不变。
- 试图保存零个用户类别 → 就地错误并阻止保存。
- 删除类别 → S13 必须先显示总数与进入未分类数；取消全部不变。确认删除当前类别后切到 S01。
- 删除卡片 → S14 明确全局影响与源文件安全；取消全部不变。

### UJ-4：修复失败入口（怡哥，外接盘位置变化后打开一张旧卡片）

1. 怡哥在 S01/S02/S03 点击卡片；应用不预检查，直接请求系统打开。
2. 请求失败后进入 S16；标题说明无法打开，正文说明卡片仍保留。
3. 他选择“重新选择文件”，进入 X01，并选中新的源文件。
4. 新文件未被其他卡片收录，原卡片仅更新文件关联；名称、备注、类别关系和各视图顺序全部保留。
5. 回到原首页上下文，底部 `status-bar` 显示“已重新关联”。
6. **Climax：** 怡哥核对原卡片仍在原位置且信息未变；应用没有自动重试打开，他再次点击时才发起新的系统请求。

Failure paths:

- X01 取消 → 原关联与全部卡片数据保持；从 S16 发起时唯一返回 S16 的“重新选择文件”，其他来源按“外部系统返回落点”逐项返回，不使用模糊的“或原上下文”。
- 新文件已被另一卡片收录 → S18 显示原卡片入口；当前卡片继续关联原路径，可重新选择或删除。
- 从 S16 选择删除 → 先进入 S14；不得从错误框直接删除。
- 同类定位失败：`action-menu` 请求 X03，失败进入 S17；重新关联、删除与关闭规则同上，且不自动重试定位。
