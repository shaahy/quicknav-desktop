## 结论

- 当前 UX Discovery 未冻结 Electron、Tauri或其他桌面框架。
- 当前 UX Discovery 未冻结 JSON、数据库或其他数据存储机制。
- 当前 UX Discovery 未定义构建、签名、安装包、升级、迁移、原子写入、损坏恢复或备份方案。
- 当前 UX Discovery 未定义路径规范化、平台大小写、符号链接/别名、网络位置表达或源文件唯一性算法。
- UX 只定义用户可观察的产品行为、状态、反馈和系统交互边界；上述技术议题仍完整归属 Architecture。
- 未发现 addendum 与已确认 Surface Closure 的产品级冲突，也未发现把已推迟技术选择反向写成 UX 决策的越界。

## UX 行为与技术实现的明确分界

### UX 可以规定

- 何时出现系统文件选择器、系统“选择打开方式”、资源管理器或 Finder，以及返回产品后的成功、失败和取消状态。
- 打开或定位失败时，卡片保持不变，并提供重新选择、删除和关闭。
- 重新关联成功后不自动重试原系统动作；用户再次触发后才产生新的打开或定位请求。
- 重复源文件冲突的文案、操作入口和数据不被覆盖的可观察结果。
- 排序、编辑、删除和类别关系变化后，用户应看到的视图落点、反馈及跨会话保留要求。

### UX 不得规定

- 使用何种桌面框架、前端栈、系统桥接库或 IPC 方案。
- 使用 JSON、SQLite、其他数据库或文件格式。
- 用规范化绝对路径、文件 ID、inode、哈希或其组合判定源文件唯一性。
- 如何实现即时写入、事务、缓存、迁移、备份或损坏恢复。
- 使用何种构建、签名、安装、更新或发布技术。

## 越界、遗漏与冲突检查

### 越界

- 未发现已确认 UX 决策越界冻结 Architecture 方案。
- `.memlog.md` 中“调整即时持久化”等表述应理解为用户可观察的保存时机和结果，不代表同步写盘、数据库事务或任何具体持久化机制；Spine 定稿时应继续维持这一措辞边界。
- “重复源文件冲突”只定义 Architecture 完成等价判定后的 UX 分支，不可被解释为 UX 已规定唯一性算法。

### 遗漏

- 没有需要补充为独立 UX Surface 的 Architecture 议题。数据迁移、损坏恢复、备份、安装和升级均不应仅因技术实现需要而生成 V1 产品页面。
- 内置、外接、网络和云盘同步位置由同一系统文件选择器承载，无需按位置类型拆分 UX 流程；实现应保证产品约束成立。
- Architecture 在进入 Epic/Story 与 QA 拆解前，仍需补齐可测试的源文件唯一性判定规则；这是技术阶段待办，不是 UX Discovery 缺口。

### 冲突

- 未发现 addendum 与 18 个产品内 Surface、4 类外部系统交互或 UJ-1 至 UJ-4 的冲突。
- “统一产品界面、原生系统交互随平台”与“双平台能力及业务规则一致”兼容，不等于指定跨平台框架。
- V1 不提供全局快捷键、主题切换或密度偏好，不影响 addendum 中任何 Architecture 约束。

## 被丢弃或不继承的定性想法

- 脑暴阶段的 Tauri 倾向未进入 UX 决策，也不构成默认 Architecture 方案。
- Electron 加常规 Web 技术仅是历史备选背景，未被 UX 采纳为实现前提。
- 跨设备路径映射因 V1 两台设备数据完全独立而不形成产品需求，UX 未设计对应入口或流程。
- 安装体积、资源占用、开发工具链熟悉度等属于 Architecture 取舍背景，未转写为视觉或交互要求。

**通过。** Addendum 的技术选择继续保持开放；UX 仅定义行为契约和系统边界。后续 Spine 若出现具体框架、存储格式、唯一性算法或打包方案，应视为越界并移除或改写为产品可观察结果。
