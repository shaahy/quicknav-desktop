## X01–X04 返回落点验证

### X01｜系统文件选择器

- 从 S01 / S02 / S03 / S05 / S06 发起并取消：回同一 Surface 的原“选择文件”。
- 从 S11 发起并取消：回 S11“重新选择文件”，保留未保存修改与原关联。
- 从 S16 发起并取消：回 S16“重新选择文件”，原关联及卡片数据不变。
- 从 S17 发起并取消：回 S17“重新选择文件”，原关联及卡片数据不变。
- 从 S18 发起并取消：回 S18“重新选择”，保留冲突上下文与原关联。
- 原触发控件因数据变化消失时：回同一 Surface 的首个安全主操作，不跳转类别、不丢弃表单状态。

上述路径不再使用“回 S16 或原上下文”等多义表述；此前 M-01 已关闭。

### X02｜系统选择打开方式

- 取消后唯一回原 `file-card` 主体。
- 卡片、类别、顺序与文件状态全部保持。
- 有效选择后由操作系统继续处理，产品不规定系统应用内部行为。

### X03｜资源管理器 / Finder

- 从主区卡片发起，系统界面正常结束且产品重新获得前台焦点：回原卡片“更多”按钮。
- 从 S11 发起：回 S11“在文件管理器中显示”。
- 定位失败：进入 S17，初始焦点落非破坏性的“重新选择文件”；关闭对话框遵循统一“还焦触发者”规则。

### X04｜操作系统安全提示

- 提示结束且产品重新获得前台焦点：回原 `file-card` 主体。
- 产品仅保留发起和回焦契约，不控制提示语言、样式、许可判断或系统执行机制。

## Architecture 边界核对

- **桌面框架：** 未选择 Electron、Tauri 或其他运行时。
- **应用数据：** 未选择 JSON、数据库、缓存结构、事务、原子写入或备份方式。
- **交付：** 未选择构建、签名、安装包、升级或卸载实现。
- **文件身份：** S18 只消费 Architecture 给出的“同一源文件”判定，不规定绝对路径、大小写、符号链接 / 别名、inode、哈希或网络位置算法。
- **系统调用：** X01–X04 只定义用户可观察结果和原生系统界面责任，不指定 API、进程模型、Shell 命令、权限桥接或调用库。
- **加载与恢复：** 冷启动只定义稳定壳、不可误操作状态、非技术化失败反馈和可见操作；加载、损坏检测、恢复、写入与重试实现均留给 Architecture。
- **持久化：** “立即生效”指无额外保存步骤的产品结果；跨关闭、重启和正常升级后的保留来自 PRD FR-026 / NFR-004，不等于同步写盘要求。
