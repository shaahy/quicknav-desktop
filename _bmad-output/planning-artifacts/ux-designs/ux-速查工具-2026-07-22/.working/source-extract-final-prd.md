# 最终上游 UX 事实提取

> 用途：供 `bmad-ux` Discovery 使用的只读事实提取。
>
> 事实优先级：`prd.md` 是唯一产品事实源；`addendum.md` 仅界定 Architecture 责任；`review-rubric.md` 仅证明 PRD Gate 状态及闭环质量，不新增产品需求。
>
> 本文不引入新需求，不冻结桌面框架、存储格式、数据库、文件身份算法、构建、签名、安装或升级方案。

## 1. 产品边界

- 产品是个人使用的 Windows 与 macOS 跨平台桌面工具，将用户主动选择的常用源文件转化为可命名、可备注、可分类、可排序、可搜索的导航卡片。
- 核心原则是“用户主动收录、应用只做导航”。应用只处理用户通过系统文件选择器明确选中的单个文件，不扫描磁盘或目录。
- 点击卡片后由操作系统处理源文件；应用不预览、渲染、编辑或改动原始文件。
- V1 面向同一位用户在一台 Windows 设备和一台 macOS 设备上独立使用。两端能力和业务规则一致，但数据彼此独立，不迁移、不同步。
- V1 不服务团队协作、共享资料库、管理员集中配置或多用户权限场景。
- 明确排除：文件管理器、文件搜索引擎、磁盘索引、自动扫描、文件夹导入、多文件批量添加、收藏、最近打开、标签、备注搜索、富文本或 Markdown 备注、图片、链接预览、附件、团队共享、多用户、权限、协作、导入导出、设备迁移、跨设备同步、共享目录、应用内文件内容处理，以及管理、修改或删除用户原始文件。
- V1 不以卡片数量、类别数量或使用频率为成功指标，不为扩大数据量引入自动扫描、批量导入或行为追踪。
- V1 不声明卡片或类别数量上限，也不承诺无限容量。
- V1 不保证卸载后保留数据，也不要求重新安装后自动恢复。

## 2. 对象与术语

- **源文件**：用户主动选择且操作系统可访问的本地文件，可位于内置磁盘、外接磁盘、网络位置或云盘同步目录。
- **卡片**：应用内指向一个源文件的唯一导航对象，包含展示名称、可选备注、文件关联和类别关系。
- **用户自建类别**：用户可创建、命名、排序和删除的一级分类对象。
- **全部卡片**：不可重命名或删除的系统视图；汇总全部卡片，每张卡片只出现一次。
- **未分类**：删除类别后，接收失去全部用户自建类别之卡片的系统恢复类别；用户不能主动选择、重命名或删除。
- **当前类别**：首页卡片主展示区当前显示的用户自建类别或系统视图。
- **主打开动作**：用户点击卡片后，应用请求操作系统按默认方式处理源文件。
- **视图顺序**：卡片在“全部卡片”、某个用户自建类别或“未分类”中的独立手动顺序。
- **备注**：最多 500 字符的可选纯文字内容。
- **文件关联**：卡片与源文件之间的关联；用户不能直接编辑路径文本，变更必须通过系统文件选择器。

## 3. 已定义的关键用户旅程

### UJ-1：首次建立导航库

主人公怡哥首次打开空应用，主动选择一个本地文件，在保存前确认步骤中创建第一个类别、确认卡片名称并保存；首页立即出现该卡片。

### UJ-2：日常快速打开

怡哥启动应用后从“全部卡片”出发，通过当前视图、切换类别或全局名称搜索定位目标卡片；点击后由操作系统按默认方式处理文件。

### UJ-3：整理同一张卡片

怡哥将一张卡片加入多个用户自建类别，并在各类别中分别调整顺序；从一个类别移出时，其他类别中的同一张卡片不受影响。

### UJ-4：修复失败入口

怡哥点击卡片后，操作系统未能打开源文件；应用明确提示失败。怡哥通过系统文件选择器重新关联文件，原卡片名称、备注、类别关系和各视图顺序保持不变。

## 4. UX 必须承载的功能、状态与异常

### 4.1 首页与导航

- 首页由常驻类别导航和当前类别卡片主展示区组成，一次只展示一个当前类别。
- 切换类别不进入新的页面层级。
- 每次启动都进入“全部卡片”；不恢复上次类别，不支持自定义启动类别。
- “全部卡片”固定在类别导航顶部；用户自建类别位于中间并保留用户顺序；“未分类”有卡片时显示并固定在底部。
- 首次启动不预置用户类别，只显示空的“全部卡片”；无卡片时应提供主动选择文件的引导。
- 首页卡片在名称下方显示最多两行备注摘要，超出省略；没有备注时不保留占位。

### 4.2 单文件收录与保存前确认

- 通过系统文件选择器一次选择一个任意类型文件；不支持多文件、文件夹导入或自动扫描。
- 取消系统选择器后不创建任何记录。
- 选择文件后必须进入保存前确认，允许确认或修改展示名称，并选择一个或多个用户自建类别。
- 无用户自建类别时，可在当前确认步骤创建第一个类别，创建后自动选中。
- 用户明确保存后才创建卡片；取消时不留下卡片或临时记录。
- HTML 默认名称优先使用去除首尾空格后的有效页面标题；标题不可读、缺失、为空或仅含空白时，回退到不含扩展名的文件名。非 HTML 默认使用不含扩展名的文件名。

### 4.3 名称校验与重复状态

- 卡片名称：单行纯文字，最多 80 字符；去除首尾空格后不可为空；不得与现有卡片名称完全相同；大小写不同视为不同名称；新增与重命名规则相同。
- 名称包含换行、超长、空白或冲突时不得保存，并给出明确反馈；名称冲突时应提示或定位同名卡片。
- 一个源文件只能对应一张卡片。重复选择已收录源文件时，不创建第二张卡片；提示“该文件已收录”，并提供查看或编辑原卡片的入口。
- 主动更换或失败修复时，如新源文件已被另一张卡片收录，必须阻止保存，提供原卡片入口，并保持当前卡片继续关联原路径；用户可改选或删除。

### 4.4 卡片查看、编辑与删除

- 卡片管理界面可查看和编辑名称、备注、类别和关联源文件。
- 管理界面只读显示完整文件路径，并支持复制路径和“在文件管理器中显示”。用户不能直接编辑路径文本。
- 主动更换源文件必须调用系统文件选择器，并保留名称、备注、类别关系和各视图顺序。
- 全局删除卡片前必须确认：卡片会从全部类别移除，但原始文件不会被删除、移动、重命名或修改。
- 确认删除后，移除卡片及其全部类别关系和视图顺序；取消后所有应用状态不变。

### 4.5 备注

- 备注为可选纯文字，最多 500 字符，换行计入字符数；纯空白按未填写处理。
- 用户可新增、编辑或清空备注；管理界面显示完整备注。
- 不支持富文本、Markdown、图片、链接预览或附件；备注不参与搜索。

### 4.6 类别管理、多类别归属与排序

- 用户可创建、重命名、删除和手动排序用户自建类别。
- 类别名称为单行纯文字，最多 30 字符；去除首尾空格后不可为空；“全部卡片”和“未分类”为保留名称；完全相同名称不可重复，大小写不同可并存；新建和重命名规则一致。
- 类别名称超长、空白、使用保留名称或冲突时不得保存，并提供明确反馈。
- 一张卡片可属于一个或多个用户自建类别，并在每个所属类别中显示。
- 正常新增或编辑时必须至少保留一个用户自建类别。
- “移出当前类别”只解除当前关系，不影响其他类别或卡片本身；卡片只属于当前类别时，不得执行该动作。
- 删除任何用户自建类别前都必须确认，包括空类别。确认信息须显示该类别卡片总数，以及删除后将进入“未分类”的卡片数。
- 删除类别只影响类别与关系，不删除卡片或源文件。仍属于其他用户类别的卡片继续保留；失去全部用户类别的卡片进入“未分类”；取消后类别、关系和顺序均不变。
- 用户不能主动把卡片加入“未分类”；卡片加入任一用户自建类别后自动离开“未分类”；进入“未分类”时追加到末尾。
- “全部卡片”、每个用户自建类别和“未分类”分别保存独立手动顺序；同一卡片可在不同视图处于不同位置。新卡片追加到“全部卡片”与每个所属类别末尾；调整一个视图不影响其他视图。

### 4.7 全局名称搜索

- 搜索范围为全部卡片，不受当前类别限制；仅搜索展示名称，不搜索备注、路径或类别名称。
- 输入首尾空格忽略，英文字母不区分大小写；采用名称包含匹配。
- 完整名称匹配优先，其次名称开头匹配，最后其他包含匹配；同一层级沿用“全部卡片”的手动顺序。
- 同一卡片在搜索结果中只出现一次。

### 4.8 主打开、选择打开方式与系统安全边界

- 点击卡片时，应用不预判源文件状态，直接请求操作系统按默认方式处理。
- 普通文件由默认应用打开；可执行文件和脚本按系统规则直接运行。产品不增加自身额外警告，但不得绕过或屏蔽操作系统安全提示。
- 文件存在但没有默认关联应用时，调用操作系统“选择打开方式”；用户取消后，不改变卡片、类别、顺序或文件状态。
- 主打开动作必须产生“成功交给操作系统”或“明确失败及可执行后续动作”的结果，不得静默失败。

### 4.9 在文件管理器中显示

- 每张卡片始终提供“在文件管理器中显示”辅助操作；Windows 使用资源管理器，macOS 使用 Finder。
- 该动作不替代主打开动作，不修改卡片或源文件；同样不预判源文件状态，直接请求操作系统定位。
- 系统无法定位时，明确提示失败，并提供“重新选择文件”和“删除卡片”。
- 定位失败或用户关闭提示后，名称、备注、类别关系和各视图顺序保持不变。

### 4.10 打开失败、重试与重新关联

- 应用不在启动时或执行主打开前检查源文件状态；不显示“检查中”，不预先标记“文件不可用”，不维护自动恢复状态。
- 操作系统无法处理打开请求时，提供明确失败反馈，以及“重新选择源文件”和“删除卡片”两个后续动作。
- 失败后不自动删除或隐藏卡片，保留名称、备注、全部类别关系及各视图顺序。
- 关闭失败提示后，用户可以再次点击卡片重试。
- 重新关联可从失败处理入口或卡片编辑界面进入，必须通过系统文件选择器，并保留卡片的其他应用内数据。

### 4.11 持久化可感知结果

- 正常关闭、重新打开、操作系统重启和应用正常升级后，卡片、名称、备注、类别、关系、视图顺序和文件关联均须保留且可用。
- 两台设备分别维护各自数据，UX 不应暗示迁移、导入、导出、同步或共享能力。

## 5. 效率、跨平台与无障碍相关约束

### 5.1 效率与可验收交互预算

- 在应用已启动并显示首页、目标卡片已收录、源文件有效、系统已有默认处理方式的前提下，从开始查找到文件成功交给操作系统处理，不超过 5 秒、2 次核心操作。
- 选择或切换类别计 1 次，输入一条完整搜索词计 1 次，点击目标卡片计 1 次；移动鼠标、滚动和等待结果不计。
- 可验收路径包括“切换类别 + 点击卡片”与“输入完整搜索词 + 点击搜索结果”。
- 系统“选择打开方式”属于异常流程，不纳入该效率指标。

### 5.2 跨平台约束

- Windows 与 macOS 的能力、业务规则和验收结果一致。
- 系统文件选择器、系统提示、默认应用处理和文件管理器定位应遵循各平台原生规范，因此原生系统交互可以存在平台差异。
- 产品不得绕过或屏蔽操作系统针对文件打开或代码执行显示的安全提示。
- UX 不得暗示 Windows 与 macOS 数据相通。

### 5.3 无障碍相关事实边界

- PRD 未定义具体无障碍标准、键盘模型、焦点顺序、读屏文案、对比度阈值、缩放或减弱动态规则。
- PRD 已冻结的、必须可被无障碍方案完整承载的行为包括：所有关键状态均有明确反馈；失败不得静默；校验错误须明确；确认对话必须清楚说明影响；核心路径受 2 次核心操作预算约束。
- 具体无障碍基线属于 UX 后续需要补足的设计契约，但不得改变上述产品行为或验收口径。

## 6. 明确留给 Architecture 的事项

- 桌面框架：Electron、Tauri 或其他方案。
- 应用数据存储格式：JSON、数据库或其他机制。
- Windows 与 macOS 的构建、签名、安装包与升级机制。
- 同一源文件的跨平台路径规范化、文件身份与唯一性等价判定算法，包括平台大小写规则、符号链接或别名、网络位置表达等。
- 数据升级迁移、原子写入、损坏恢复与备份策略。
- 实际可承载的卡片与类别规模。
- 上述实现选择必须满足既定产品语义，尤其是“一源文件一卡片”、正常关闭/重启/正常升级后数据保留、不扫描、不主动检查文件状态、支持系统可访问位置和任意文件类型、不修改源文件、双设备独立。
- 源文件等价判定必须在进入 Epic/Story 与 QA 用例拆解前由 Architecture 确定，并使“一源文件一卡片”可测试。

## 7. PRD 未冻结、仍需 UX 决策的点

以下仅表示产品规则已给出而界面表达未冻结，不代表可改变 PRD 语义：

- 类别导航位于左侧还是顶部。
- 首页卡片主展示区的具体布局、信息密度和视觉层级。
- 保存前确认、卡片管理、类别管理、删除确认及失败反馈采用何种界面容器和页面关系。
- 在“单击卡片即执行主打开”的前提下，查看/编辑、辅助操作、多选类别和手动排序入口如何被发现并避免误触。
- 用户自建类别排序与各视图卡片排序的具体交互机制。
- 全局搜索入口、输入状态、结果呈现、空结果与退出/返回当前类别的交互表达。
- 首次空状态如何引导选择文件，以及确认步骤中创建第一个类别的具体交互。
- 重复源文件、同名卡片、类别重名/保留名、长度超限和必填校验的反馈位置、时机与原卡片入口表达。
- “移出当前类别”禁用条件和解释方式。
- 删除类别确认中“类别卡片总数”与“将进入未分类数量”的信息层级。
- 主打开失败与定位失败的反馈形态、关闭方式、重试/重新选择/删除入口层级；两条失败路径必须保持 PRD 指定的数据不变语义。
- 路径只读展示、复制路径与在文件管理器中显示的管理界面布局。
- Windows 与 macOS 在业务一致前提下，哪些界面细节跟随平台原生习惯。
- 键盘操作、焦点管理、读屏语义、对比度、缩放、减弱动态等无障碍基线。
- 视觉品牌、颜色、字体、间距、形状、层级、动效与组件视觉规范。

## 8. 上游完成度与 UX 使用提醒

- 最终审查确认 FR-001—FR-026、UJ-1—UJ-4、NFR-001—NFR-007 连续且唯一，产品级开放问题为零，未确认假设为零。
- FR-019 的定位失败分支已经闭环，与 FR-020—FR-022 的主打开失败、修复入口和数据保持口径一致。
- UX 可以直接提取界面状态、平台约束和验收结果，但不得把 Architecture 待定事项包装成 UX 已冻结事实。
- UX Discovery 中若出现与本文事实冲突的旧脑暴、旧记录或定性灵感，以最终 `prd.md` 为准。
