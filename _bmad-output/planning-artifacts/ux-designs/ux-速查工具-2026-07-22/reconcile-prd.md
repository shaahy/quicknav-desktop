# 最终 PRD 与 UX Discovery 对账

## 1. 对账结论

- 最终 PRD 是本报告唯一产品事实源；`.memlog.md` 与 `.working/ia-closure.md` 仅用于检查产品事实是否已被 UX 决策和 Surface 承载。
- UJ-1 至 UJ-4 均已形成端到端 Surface 闭环；FR-001 至 FR-026 均有明确的 UX 承载、行为契约落点，或被正确保留为 Architecture / 实现验收边界。
- 未发现已确认 UX 决策与最终 PRD 的实质冲突，也未发现需要新增独立页面的产品需求。
- 发现 8 组 PRD 细节尚未在 Discovery 决策中逐字展开，Finalize 蒸馏时必须直接继承到 `EXPERIENCE.md`，不得把它们当作开放问题或另行改写：默认名称提取、卡片名称校验、类别名称校验、“未分类”显示条件、搜索字段与归一化、系统打开方式取消结果、备注校验、数据持久化结果。
- 有 1 处措辞风险：memlog 中“未分类在存在卡片时固定底部”必须解释为“仅在未分类中存在卡片时显示”，不能解释为“只要应用中存在任意卡片就显示”。
- UX Discovery 新增的是界面层决策（布局、组件形态、视觉语言、无障碍、焦点与反馈），没有冻结 Electron、Tauri、JSON、数据库、文件身份规范化、打包、安装或升级实现。

## 5. 术语一致性

| PRD 术语 | UX 使用情况 | 约束 |
|---|---|---|
| 源文件 | 用于文件选择、打开、定位、重新关联与安全说明 | 不得简化为由应用管理的“文件”；应用只保存关联，不拥有源文件。 |
| 卡片 | 网格中的唯一导航对象；主体负责主打开，“更多”负责管理 | 不得称为副本、快捷方式文件或文件记录，以免暗示修改源文件。 |
| 用户自建类别 | 左栏中部可创建、重命名、删除、排序的一级对象 | 不得引入文件夹层级、标签或“主类别”。 |
| 全部卡片 | 固定顶部的系统视图，汇总唯一卡片 | 不得改名、删除、排序到其他位置或按多类别重复展示。 |
| 未分类 | 恢复专用系统视图 | 仅含失去全部用户类别的卡片；不得主动选择、改名、删除；仅非空时显示。 |
| 当前类别 | 左栏保持选中的系统视图或用户类别 | 搜索期间保留该上下文，退出搜索后恢复。 |
| 主打开动作 | 单击卡片主体，请求操作系统按默认方式处理 | 与“在文件管理器中显示”和卡片管理严格分离。 |
| 视图顺序 | 每个系统视图/用户类别各自独立的手动顺序 | 不得用一个全局顺序替代所有视图顺序。 |
| 备注 | 最多 500 字符的可选纯文字 | 首页仅两行摘要；不参与搜索，不支持富内容。 |

## 6. 范围与 Architecture 边界

### UX 已正确排除

- 文件管理器、磁盘索引、自动扫描、文件夹导入、多文件批量添加。
- 收藏、最近打开、标签、备注搜索。
- 富文本、Markdown、图片、链接预览、附件和应用内文件内容预览。
- 团队、多用户、权限、共享与协作。
- 数据导入导出、设备迁移、跨设备同步。
- 管理、修改或删除用户原始文件。
- 独立类别管理页和独立卡片详情页。

### 不得由 UX 冻结

- Electron、Tauri 或其他桌面框架。
- JSON、数据库、文件系统或其他本地数据格式。
- 文件身份的路径规范化、inode、文件 ID 或其他算法。
- 数据迁移、正常升级持久化的技术实现。
- 打包、签名、安装、卸载和发布方案。
- 实际容量上限与性能技术指标。

## 7. 已确认的 UX 层补充决策

以下内容不是对 PRD 产品范围的扩写，而是履行 UX 阶段职责的界面契约，可进入 Spine：

- 固定左侧类别栏、右侧响应式卡片网格；常规 1024×720，最小约 760×560，窗口向更大尺寸自由调整。
- 卡片主体单击打开，常驻独立“更多”按钮；卡片和类别均采用显式整理模式。
- 新增/编辑使用居中模态框；类别新建/重命名使用锚定浮层；删除与错误使用居中对话框。
- 全局名称搜索常驻、实时更新，搜索期间保留左栏当前类别上下文。
- 非阻断成功反馈使用主区域底部状态条；重新关联后不自动重试系统动作。
- 仅简体中文、冷静直接工具化文案、浅色“结构化索引 + 档案绿标”、系统无衬线正文与等宽辅助信息。
- 桌面 AA 无障碍基线、全键盘可达、可见焦点、读屏语义、减少动态效果；不设置全局组合快捷键。
- 应用内界面跨平台统一，系统交互遵循 Windows/macOS 原生规范。

## 8. 遗漏、冲突与被丢弃的定性想法

### 8.1 Finalize 必须补齐的 PRD 原有细节

1. HTML `<title>` 与文件名的默认卡片名称优先级。
2. 卡片名称 80 字符、单行、去空格、唯一性和大小写规则。
3. 类别名称 30 字符、单行、保留名称、唯一性和大小写规则。
4. “未分类”仅在自身非空时显示，新进入卡片追加末尾。
5. 搜索只查名称、查询去首尾空格、英文不区分大小写。
6. 没有默认应用时由系统选择打开方式，取消不改变任何状态。
7. 备注 500 字符、换行计数、纯空白与禁用富内容规则。
8. 正常关闭、重开、系统重启、正常升级后的持久化结果，以及卸载/重装边界。

这些均应直接从 PRD 继承，不需要再次向用户提问。

### 8.2 冲突

- 无实质冲突。
- 唯一措辞风险是 memlog 的“未分类在存在卡片时固定底部”；Finalize 必须采用 PRD 的精确定义“未分类中存在卡片时才显示”。
- “文件类型图标与扩展名不读取或预览文件内容”仅描述类型标识的生成方式，不得扩大解释为禁止 FR-002 对 HTML `<title>` 的读取。

### 8.3 被丢弃或未采纳的定性想法

- Discovery 明确不采用旧脑暴对账、结构润色和文案润色过程文件；因此不存在需要从这些过程文件回填的定性想法。
