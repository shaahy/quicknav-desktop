# 页面空白排查与修复

状态：已修复，带一项测试基础设施说明

## 现象

运行 `npm run dev` 后，Electron 窗口可以打开，但 Renderer 区域完全空白。

## 证据与结论

### 根因

提交 `4170ec3` 为 Ctrl+Q 快捷键新增了一个 `useEffect`，但该 Hook 位于
`loadingState === 'loading'` 的提前返回之后。

应用首次渲染只调用 66 个 Hook；本地数据加载完成后，Renderer 再次渲染并调用
第 67 个 Hook。React 因此抛出：

```text
Rendered more hooks than during the previous render.
```

异常发生在 `src/renderer/components/app-shell.tsx:697`（修复前行号），导致整个
Renderer 卸载，最终表现为 Electron 窗口存在但内容区完全空白。

`app-data.json` 本身包含现有卡片，Main IPC 的读取路径也能返回数据，因此“数据
为空”不是根因。

### 修复

- 将 Ctrl+Q 的 `useEffect` 移到 loading 条件返回之前，保证所有渲染分支的 Hook
  调用顺序一致。
- 新增 `loading -> ready` 组件重渲染回归测试。该测试在修复前稳定失败，在修复后
  通过。

### 验证

- 聚焦回归：`tests/unit/app-shell.test.tsx`，6/6 通过。
- 全部测试：14 个测试文件逐文件隔离运行，143/143 通过。
- TypeScript：`npm run lint` 通过。
- 生产构建：`npm run build` 通过，Main、Preload、Renderer 均成功构建。
- 现场验证：2026-07-24，用户重新查看开发应用，确认界面已有内容。
- `git diff --check`：通过。

### 测试基础设施说明

当前环境是 Node 24.15.0、Vitest 2.1.9。默认 `npm test` 的 worker 在该组合下出现
`Worker exited unexpectedly`；强制所有测试共享单线程时，又会暴露既有的测试文件
间全局状态污染。逐文件隔离后 143 项全部通过，证明本次修改没有引入测试回归。

该测试运行器兼容问题与本次白屏根因无关，本次未升级依赖或扩大为工具链迁移。
